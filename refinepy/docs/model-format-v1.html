Model manifest v1

Explicitly configured TOML manifests describe value/container signatures and read-only snapshot effects without importing Python modules. A model is a trusted claim about one fixed direct function and its initialization, not verification of the external implementation. Source functions take precedence when a configured source root supplies their module.

Set model-files = ["models/vendor.toml"] under [tool.refinepy]. Paths are relative to the configuration directory. Unknown fields, missing required fields, wrong field types, invalid binders, unsupported effects and compatibility failures produce error: invalid-model; no stub fallback is applied.

schema_version = 1
python_version = "3.12"

[runtime]
implementation = "vendor-dist"
version = "1.0"
metadata = "vendor-dist-1.0.dist-info/METADATA"

[[models]]
symbol = "vendor.step"
requires = ["lambda x: x >= 0"]
ensures = ["lambda result, x: result == x + 1"]
definedness = ["lambda x: x >= 1"]
raises = []
reads = []
writes = []
allocates = []
implementations = ["vendor-dist==1.0:vendor.step"]
provenance = "Reviewed scalar specification for vendor-dist 1.0"
version = "1"
hash = "derived"

[[models.initializer_assumptions]]
module = "vendor"
version = "1"
description = "Inert initialization and fixed direct symbol"

[models.signature]
returns = "int"

[[models.signature.parameters]]
name = "x"
type = "int"
mode = "positional-or-keyword"

The metadata file must contain exactly one Name: vendor-dist line and one Version: 1.0 line for this example. Its path is relative to the manifest. The user supplies the installed distribution metadata; refinepy reads those bytes and compares exact names and versions. It does not inspect executable Python, consult an active interpreter’s import path, or establish that a deployment uses that distribution. The fixed implementation and deployment correspondence remain internal assumptions. These are useful static compatibility checks, not runtime attestation. Synthetic metadata in the tests is deliberately a trust fixture.

Field contracts

Location Fields and exact types
Manifest schema_version: integer, exactly 1; python_version: string, exactly 3.12; runtime: table; models: array of tables
Runtime implementation, version, metadata: nonempty strings; metadata must exist and match the exact distribution name and version
Model symbol, provenance, version, hash: strings; signature: table; every predicate/effect/implementation field: array of strings; initializer_assumptions: array of tables
Signature parameters: array of tables, including an explicit empty array for a zero-argument function; returns: supported annotation string
Parameter name, type, mode: strings; optional default: TOML integer, boolean, or signed decimal integer string
Initializer module, version, description: nonempty strings

Symbols and parameter names use ASCII Python identifier spellings. Parameter names are unique; symbols have a module and function component. Modes are positional-only, positional-or-keyword, or keyword-only, in that order. A required positional parameter cannot follow a positional default. Defaults have int/bool literal semantics; decimal strings preserve arbitrary-precision integers beyond TOML’s integer range. The definition checks default base types; each call checks its instantiated dependent refinement.

Parameter type and result strings use the value annotation DSL, including Annotated[T, Refine(lambda ...)] contracts with the resolved inert marker. Assert is a source-local operation and cannot appear in model types. Parameter refinements may name earlier formal inputs; result refinements may name any entry input, following the source binder convention. No project aliases or arbitrary Python expressions are evaluated. Use Sequence and Mapping for built-in list/tuple and dict inputs, or invariant list/dict types. Elements/values must be nonoptional scalars, and mapping keys must be plain str. Element refinements stay at their type nodes. Fixed product fields may recursively contain these containers and optional values. A product containing containers counts as a container input for reads; allocation declarations still do not certify caller-side list mutation. Outer result predicates may be specified in ensures.

requires and definedness strings are single-line literal lambdas whose binders name entry inputs. ensures lambdas bind the result first, then named entry inputs. Duplicate, unresolved, unsorted or non-bool predicates are errors. The same frontend parses source contracts and model predicates. Guarded sequence indexing and mapping lookup are admitted. Before using a model summary, the checker proves precondition/definedness totality without assuming those predicates themselves, and postcondition totality from the input contract and arbitrary result base value. Separate postcondition predicates cannot justify each other’s definedness. Body calls remain outside this DSL.

At each call, every parameter refinement, requires predicate and definedness predicate is a final proof obligation. The postcondition describes an arbitrary normal result and becomes usable only within a proof whose preceding obligations all succeed. The model does not supply a concrete result for witness replay.

The contract requires raises and writes to be empty. reads conservatively names every container input exactly once, using its parameter name; optional container inputs count as dependencies. No omitted input, duplicate, nested selector or global selector is accepted. allocates is either empty or ["return"] for a container result (including an optional container). That selector claims a fresh result on normal returns with a container value. It supplies no observable identity or non-aliasing formula: those operations remain unsupported.

For example, a copy model can declare x: Sequence[int], return list[int], use reads = ["x"], writes = [], allocates = ["return"], and specify ensures = ["lambda result, x: len(result) == len(x)"]. This only establishes length preservation; element equality would need an additional supported contract. Empty writes/raises and freshness are trusted claims, not checks of the external implementation. Unknown calls, callbacks, globals, I/O and method dispatch have no model semantics. implementations must be the single exact string distribution==version:resolved.symbol matching the manifest runtime. There is no overload selection or version-range matching.

Each external module initialized by an import needs a versioned assumption, including all parents of a modeled submodule. Project-source parent initializers are checked instead. A child model cannot bypass an unsupported parent initializer. Initializer and implementation assumptions are retained internally even when the import is used only for module initialization and the modeled function is not called.

Identity and hashing

hash is required and its only admitted value is derived. No user-provided checksum is accepted as already validated. src/models/mod.rs serializes the strictly typed model record to JSON in struct-field order, appends the exact runtime metadata bytes and refinepy-model-v1-python3.12-m5, and derives SHA-256. The reported identity includes the resolved symbol, model version, derived hash and exact runtime distribution version. The derived digest is not stored back into the manifest. TOML table/key order and formatting do not affect it; predicate strings and array order are part of the record and do affect it.

Models are loaded afresh for each requested selector. Source module hashes and verified dependency origins are reported alongside model identities. Opt-in verified-closure caching includes model, runtime metadata and source dependencies in its invalidation contract.
