refinepy specification

Specification v0.4, October 1, 2026.

refinepy statically verifies the restricted Python 3.12 subset defined here. It reads typing.Annotated metadata as a predicate language, builds ordered CFG, SSA and ANF representations in Rust, and checks refinement obligations using finite qualifier inference and an isolated Z3 worker.

This is the canonical specification for the current implementation. The Python support matrix records exact admitted forms and their restrictions. The model manifest v1 and report/cache/control v3 define the external contracts. The verification contract is conditional on the stated runtime and trust assumptions; it is not a formal soundness theorem.

The supported domain is annotated, first-order computational helpers over integers and stable built-in containers within regular Python packages. Exclusive local list construction and element writes are admitted with a checked non-aliasing certificate. Deliberate exceptions, arbitrary application code and general shared-heap mutation are excluded.

Verification contract and supported scope

Meaning of verification

The intended guarantee for a function reported as verified is:

If its inputs satisfy the base types, preconditions, and modeled-runtime assumptions, and no external interference changes observed state, execution does not encounter a modeled runtime error, and any normal return satisfies the return refinement.

This combines partial correctness with freedom from the modeled errors. Termination is additional evidence for the restricted measured call closures described under decreasing measures. Resource exhaustion (including Python recursion-depth exhaustion and its RecursionError), asynchronous exceptions, and process termination are outside the model. A verified status alone does not imply termination; reports distinguish the additional evidence.

Annotations alone cannot establish these assumptions for arbitrary Python callers. At external boundaries, input contracts and supported object implementations are assumptions. At checked calls, the verifier proves the corresponding obligations. Custom subclasses of int, custom Sequence implementations, and overridden operators are not silently assigned built-in semantics.

The frontend reads complete modules without executing them, but verifies explicitly selected functions and their required dependencies. The following boundary rules determine when unrelated code can remain unchecked.

Verification boundaries and project resolution

Select targets by a resolved module:function name or the module selector module:*, which expands to its top-level annotated function declarations. Report the expanded target list and retain excluded declarations internally; do not describe this as verification of all module code. Resolve the transitive call, type, constant, and model dependencies of each target. Unselected ordinary function bodies may contain unsupported code; they remain unchecked and contribute no contracts. A source function used as a callee must itself verify. Direct self-calls use the declared contract under the partial-correctness rule below; mutual recursion remains unsupported.

Module initialization is a separate boundary. An unused function body is inert at import, but its decorators, defaults, and eagerly evaluated annotation expressions may not be. Accept only statically modeled declarations and initializers by default. An unmodeled initialization effect in a relevant module produces unsupported. To admit a third-party module through a model, require an explicit versioned initializer assumption in the model manifest; retain it internally. Selecting a function never silently asserts that its module’s arbitrary initialization is harmless.

Resolve regular packages within configured source roots, including __init__.py and relative imports. Reject ambiguous duplicate module candidates, star imports, dynamic imports, and namespace-package composition in the supported subset. Follow explicit re-exports to the original symbol. Read declarations across import cycles, but reject cyclic alias expansion and unresolved initialization dependencies. No resolver step imports or executes Python code.

Use project source when available. Stub-only external symbols require an explicitly registered model; .pyi base types do not establish purity or refinements. if TYPE_CHECKING imports are available for static annotation resolution only and do not establish runtime callable bindings. Recognize from __future__ import annotations as a compiler directive. Runtime annotation evaluation is never used to resolve contracts. See typing distribution rules.

Allow immutable module constants formed from supported scalar literals and closed constant expressions, including nonzero-constant floor division and modulo. Reject rebinding of a constant used in a proof. Model-supported declaration calls such as constrained TypeVar are recognized syntactically, not executed. The versioned built-in registry includes the declaration/import behavior needed for supported typing, collections.abc, and companion-marker/decorator forms; this is an internal runtime assumption, not verification of those modules. Other top-level calls require the initializer policy above. Imports inside checked function bodies are unsupported.

Input files use UTF-8, with an optional UTF-8 BOM or compatible encoding declaration; reject other declared encodings in the supported subset. Follow Python’s identifier normalization, retain original spelling and source bytes, and use original byte spans internally and in the current diagnostic interface. Comments, parentheses, semicolon-separated statements, and line continuations follow the Python 3.12 parser. Nonformatted string prefixes, escapes, and adjacent literals must preserve exact code points. F-strings and ellipsis values are explicitly unsupported. See Python lexical rules.

Declarations may be discovered before initialization, but eager annotations and constant/alias assignments can use only runtime bindings already established. Regular parent packages participate in initialization; external parents require explicit model assumptions. An implicit submodule binding that would overwrite a declared parent constant, function or alias is rejected. Project files cannot shadow the built-in typing/collections declaration registry. A local companion replacement is recognized only when its bytes match the compiled inert companion.

Base typing and value joins

Use bidirectional base typing before refinement generation. Function parameters and returns require annotations; a missing annotation is an error, not implicit Any. Infer supported local types from their RHS or check them against an explicit local annotation, formal parameter, or return expectation. Contextually type empty list/dictionary literals; without an expected element/value type, report error: cannot-infer-empty-container rather than inventing a dynamic element type.

The leaf types are int, bool, str, and None. Lists/sequences and string-keyed dictionaries/mappings may recursively contain any supported value type. Fixed tuples have zero or more supported value fields, each with its own type and refinement. Fields may be None, optional values, other fixed tuples, or supported containers. Element contracts recursively check product fields, optional payloads and valid nested container domains. An optional wraps any one supported nonoptional type. Normalize Optional[T] and T | None to the same tagged type; general unions remain unsupported.

Join equal base types directly, bool/int by numeric embedding, fixed tuples fieldwise when their arity matches, and T with None as Optional[T]. Combine optional payloads only when the corresponding nonoptional join is supported. General container joins follow their declared variance; an implementation must not manufacture writable covariance. Refinement facts at joins still come from relational predicates, not intersecting incompatible paths.

Any, object, unresolved types, cast, TypeGuard, TypeIs, Final, and NewType have no proof semantics in the supported subset and are rejected at checked boundaries. A trusted model must expose a supported concrete signature instead. Type comments and # type: ignore do not supply types or suppress obligations; retain them internally as unused typing directives. Do not claim compatibility with every ordinary Python type checker.

Literal value contracts

Translate a nonempty typing.Literal[...] into one supported base type and a unary predicate selecting its allowed values. Admit int (including signed literals), bool, str and None, provided every argument has the same base type. Duplicates do not change the contract. Resolve imported/qualified Literal names, static type aliases and quoted annotations through the normal annotation rules. Compose Literal with Annotated, optional payload contracts, product field contracts and scalar container element contracts. Preserve the existing invariance of writable container interfaces.

Reject mixed base types (including mixed int/bool), computed or named arguments, enum values, nested Literal applications and empty argument lists. String arguments are literal contents, not forward references. Integer Literal follows the existing numeric embedding: True satisfies Literal[1] and False satisfies Literal[0]. Literal[True] has bool base and excludes integer 1. Literal[None] has singleton None base; the existing restrictions on optional payloads, container elements and tuple fields still apply. Defaults remain base-checked at definition and refinement-checked at each actual call.

Constrained scalar generics

Admit one constrained type parameter per first-order function, declared with Python 3.12 type-parameter syntax or a module-level TypeVar. Require at least two distinct constraints from int, bool, and str; reject a constraint set containing both int and bool to avoid overlapping specializations. Thus the supported choices are the pairs int/str and bool/str. Check every declared specialization, even if no current call uses it. Generic aliases, unconstrained/bounded-only parameters, higher-kinded types, variance annotations, and multiple type parameters are unsupported. See constrained type variables.

The parameter substitutes base types only, including scalar container elements and tuple fields. It does not introduce abstract refinement polymorphism: passing Sequence[Nat] through a helper returning unconstrained T does not automatically preserve Nat. A stronger result requires an explicit or verified relational summary. Calls choose a unique admitted specialization after base typing; zero or ambiguous matches fail. All specializations must verify before the generic definition is reported as verified.

from collections.abc import Sequence

def first_or_none[T: (int, str)](xs: Sequence[T], /) -> T | None:
    if xs:
        return xs[0]
    return None

Check its integer and string variants separately; the true branch establishes a nonempty sequence, and the return join introduces the optional tag.

Surface syntax and binding

Basic syntax

from refinepy import Refine
from typing import Annotated
from collections.abc import Sequence, Mapping

Nat = Annotated[int, Refine(lambda v: v >= 0)]
NonEmptyNats = Annotated[Sequence[Nat], Refine(lambda xs: len(xs) > 0)]
HttpPorts = Annotated[Mapping[str, Nat], Refine(lambda m: "http" in m)]

def first(xs: NonEmptyNats) -> Nat:
    return xs[0]

def http_port(ports: HttpPorts) -> Nat:
    return ports["http"]

Sequence[Nat] constrains each element; the outer Annotated constrains the sequence as a whole. Preserve these at their respective type nodes.

Existing type checkers can ignore unfamiliar Annotated metadata while checking the base type. This permits coexistence, but does not mean those tools verify refinepy predicates. See PEP 593.

Within explicitly selected source files, Annotated[T, Refine(lambda ...)] declares a refinement when the marker resolves to refinepy.Refine. Require one positional literal predicate lambda and no keywords. Multiple Refine markers are checked individually and their predicates are conjoined. Resolve markers through imports, aliases and re-exports. Preserve other admitted metadata as opaque information; it contributes no proof facts. A malformed marker or unsupported predicate is an annotation error. A referenced callable outside the marker remains opaque metadata and emits metadata-not-verified.

The inert companion stores the predicate without invoking it. The verifier reads source, never runtime annotation objects. Assert is a separate point-local operation, specified under static assertions; it is not a refinement contract.

Dependencies on function inputs

def increment(x: Nat) -> Annotated[int, Refine(lambda result, x: result == x + 1)]:
    x = x + 1
    return x

def at(
    xs: Sequence[int],
    i: Annotated[int, Refine(lambda v, xs: 0 <= v < len(xs))],
) -> int:
    return xs[i]

Binding rules:

  1. The first lambda parameter denotes the refined value. Its spelling is arbitrary; internally it becomes a fresh binder ν.
  2. In a parameter annotation, subsequent lambda parameters name earlier function parameters. Reject forward, self, and cyclic dependencies.
  3. In a return annotation, subsequent lambda parameters may name any function parameter.
  4. Dependencies denote function-entry values such as x₀. Reassigning x in the body does not change this binding. The example checks result = x₀ + 1.
  5. The first parameter always denotes the refined value, even if its spelling matches a function parameter. Use names such as v or result when that distinction could be confusing.
  6. Initial aliases and local variable annotations accept unary predicates only. Function inputs cannot be captured as free variables. Callable names resolve to registered built-in models or explicitly reflected definitions over supported value types.

Predicate lambdas accept only ordinary required positional parameters. Defaults, *args, **kwargs, and assignments inside predicates are unsupported. These dependency rules are refinepy’s static convention, not Python’s runtime annotation binding semantics.

A local Refine declaration such as x: Nat = ... establishes a contract for subsequent assignments to that source local. In contrast, a parameter refinement is an entry precondition; it is not automatically an invariant on every later reassignment of the same local name.

Static assertions

A declaration-only function-local annotation x: Annotated[T, Assert(lambda v: P(v), using=lambda v: lemma(v))] checks a proposition about the current, definitely assigned value of x. Assert must resolve to refinepy.Assert. Require exactly one Assert metadata marker, one positional literal predicate lambda, and optionally one using keyword containing a literal lambda. Both first binders denote the current value regardless of their spelling. Later binders explicitly name definitely assigned locals at this source position, not their function-entry values. The two lambdas may name different dependency lists. Bind these dependencies to current SSA values; rebinding a local never updates a previously established assertion. Defaults, duplicate binders, variadic parameters, unresolved dependencies and free local captures are unsupported. Base T may include existing Refine contracts, which must also hold at this point; its base sort must match the current value without conversion.

from typing import Annotated
from refinepy import Refine, Assert

Nat = Annotated[int, Refine(lambda v: v >= 0)]

def f(n: Nat) -> int:
    x = n
    x: Annotated[Nat, Assert(lambda value: value >= 0)]
    x = -1
    return x

Assert does not assign a value, change its type or replace/install a persistent local contract. Facts refer to the current SSA binding; rebinding does not transfer them to the new value. Repeated static assertions are allowed. Existing declaration contracts still constrain subsequent assignments. Assertions are checked under incoming path facts and their definedness is checked at the source point, not as a function-entry annotation. Assert without using proves its proposition from the existing context and admitted reflected equations.

using must contain one direct call to a source lemma returning refined None. Its argument expressions use only the first value binder and explicitly listed current-local binders in the logical expression subset: no unreflected nested calls, arbitrary code or result capture. Check argument definedness, parameter contracts and preconditions before importing the lemma’s postcondition; the assertion goal cannot justify those checks. The dependency closure must independently verify with mathematical termination evidence, including ordinary recursive lemmas’ checked descent. Partial-correctness summaries, trusted external models, loops, mutual recursion and a using self-call do not establish an erased theorem. An ordinary decreasing self-call inside the lemma continues to use the existing inductive rule. Side effects and unsafe operations remain excluded by the checked source subset and stable-state assumptions. Reflected definitions are admitted independently.

Use the admitted lemma’s instantiated postcondition to prove the assertion predicate; the lemma’s proposition need not be identical. A wrong goal, failed dependency, failed precondition, unproved termination or solver uncertainty cannot publish assertion success. Established theorem facts and assertion facts are available to subsequent checks. Descent verification removes those facts just as it removes ordinary call summaries and assertions. static-assertion-definedness and static-assertion identify the obligations; static-lemma:<identity>:verified; erased from Python execution records admitted erased calls. Source identities, bodies and assertion annotations participate in dependency and cache invalidation.

Allow only unquoted declaration-only annotations of simple bound function locals. An initializer, an unbound target, incompatible base sort, nested Assert, multiple metadata items, type alias, module variable, parameter or return annotation is invalid. Refine continues to describe contracts rather than point-local operations. Supporting lemmas remain ordinary checked functions; this feature does not replace their runtime definitions.

Python does not evaluate function-local annotations, so neither marker construction nor either lambda nor the supporting call executes at this site. The companion Assert(predicate, *, using=None) stores callables without invoking them if constructed explicitly. No unchecked assumption, runtime validation, source rewriting or decorator wrapping is introduced. The model remains mathematical and does not guarantee resource availability or Python recursion-depth safety.

Function preconditions and invariant directives

Function contracts use @refinepy.requires(lambda ...), @refinepy.ensures(lambda ...), @refinepy.decreases(lambda ...), and bare @refinepy.reflect. Multiple requires decorators are conjoined; multiple ensures decorators add conjoined return refinements; at most one decreases and one reflect are permitted. Decorator order does not change these static contracts. Require exactly one positional literal lambda for requires, ensures and decreases; reject keywords, argument expansion, callable references and lambda defaults or variadic parameters. Normal Python parentheses permit multiline lambdas.

Resolve decorator identities through regular imports, module aliases, imported aliases and re-exports. from refinepy import requires as pre permits @pre(lambda ...); a same-named user function does not supply a contract. Decorator heads must be available when the function is defined; TYPE_CHECKING imports cannot supply them. The trusted companion returns the exact original function and never invokes the predicate, enforces a runtime contract or wraps the function. Its typed interfaces preserve the callable type. Python execution requires the companion package; verification reads source without importing it. Any other decorator remains unsupported, including on an unselected function. Validate decorator argument construction at initialization even when annotations are postponed.

ensures is sugar for a return Refine predicate, not an unchecked assumption. An explicit return annotation remains required. For any return base other than None, the first required lambda parameter denotes the result regardless of its name; additional parameters name immutable function-entry inputs in any order. For a None return base, every lambda parameter names an entry input and no result binder is written; lambda: proposition is allowed. Resolve the annotated base (including aliases) before selecting this rule. A None postcondition lowers to an ordinary return predicate with a fresh unused result binder.

from refinepy import ensures

@ensures(lambda result, n: result == n + 1)
def increment(n: int) -> int:
    return n + 1

@ensures(lambda n: n + 0 == n)
def identity_lemma(n: int) -> None:
    return None

Repeated ensures and existing return Refine metadata are conjoined. Each predicate undergoes the existing return-annotation definedness checks over the return base domain and admitted entry contracts, without assuming any sibling postcondition. Every return must establish all predicates. Verified ordinary calls, recursive hypotheses and static lemma applications use the resulting contract exactly as for an annotated return refinement. Refined-None induction and independent termination admission are unchanged. Reflection still requires plain return contracts and rejects ensures. The companion returns the original function without evaluating predicates, wrapping calls or modifying annotations.

Use ordinary refinepy.invariant(lambda ...) and refinepy.decreases(lambda ...) expression statements immediately before a while or supported for. Resolve the same trusted identities, aliases and re-exports as decorators; runtime marker heads cannot come from TYPE_CHECKING. Consecutive invariant calls are conjoined and at most one loop measure is permitted. Every call takes exactly one positional literal lambda with ordinary required parameters. Blank lines and ordinary comments may intervene, but no other statement may intervene and the loop must be in the same block. Calls are static markers, not body-call dependencies. Python executes the marker call once before reaching the loop, creating the lambda but never invoking its body; invariant returns None, and decreases returns the existing identity decorator, whose unused result has no effect. Neither call asserts a runtime property or binds a local.

The deprecated # refinepy: invariant lambda ... compatibility form remains accepted. It occupies a single physical line and attaches to the following while or supported for at the same indentation. Blank lines and ordinary comments may intervene, but no executable statement may intervene. Multiple invariant lines are checked together. Function-comment directives (requires, reflect, decreases) are rejected without compatibility for those function forms. Unknown directives, malformed attachment, duplicate lambda parameters and unresolved binders are errors.

import refinepy
from collections.abc import Sequence

@refinepy.requires(lambda xs, n: 0 <= n <= len(xs))
def prefix_bound(xs: Sequence[int], n: int) -> int:
    i = 0
    refinepy.invariant(lambda i, n: 0 <= i <= n)
    while i < n:
        i += 1
    return i

Every lambda parameter in a requires/decreases decorator or loop marker names an existing source binding; there is no distinguished refined-value parameter in those markers. A function precondition binds any function-entry inputs, regardless of declaration order, and is conjoined with parameter contracts. Prove its definedness from base types and established parameter contracts, without assuming its own truth or another requires condition. Check the combined precondition at calls and use it in the callee only as its declared input assumption.

An invariant binds current loop-header values, including loop-carried locals and invariant captures. A possibly unbound loop target cannot appear in the invariant unless it has been initialized independently. Source locals reassigned inside the loop denote their current header versions, not their function-entry values. Generated iterator counters are not exposed as source names.

User invariants are fixed assertions, checked for definedness, initiation, and preservation on every back edge. They may be combined with inferred predicates but never weakened. Their facts can be used in the body and appropriate exits only as part of a verification whose invariant obligations all succeed. Invalid hints cannot make an otherwise invalid function verified. User-defined qualifier directives are unsupported; checked invariants provide the recovery mechanism.

The earlier-parameter rule for dependent parameter annotations is unchanged; use requires for a relation involving later parameters. Keep same-position metadata totality checks independent. Cross-metadata composition outside these rules is unsupported; circular assumptions cannot justify verification.

Reflected definitions and lemmas

A bare @refinepy.reflect decorator marks a top-level function. Exactly one marker is permitted; parentheses are rejected. Reflection is explicit and checked; it is not an assumed postcondition or permission to execute annotations.

from __future__ import annotations
import refinepy
from refinepy import Refine
from typing import Annotated

@refinepy.reflect
def inc(x: int) -> int:
    return x + 1

@refinepy.reflect
def twice(x: int) -> int:
    return inc(inc(x))

def lemma_twice(x: int) -> Annotated[
    None, Refine(lambda _, x: twice(x) == x + 2)
]:
    return None

def use_lemma(x: int) -> Annotated[int, Refine(lambda r, x: r == twice(x))]:
    lemma_twice(x)
    return x + 2

Admit loop-free bodies with local assignment/rebinding, flat tuple unpacking, local declarations, assertions, if/elif/else branches and returns, optionally preceded by a docstring. Bare return and fallthrough use the usual None typing. Parameters and result may use any supported value type: scalars, None, optionals, fixed products, lists/sequences with supported elements and string-keyed mappings/dicts. Every nested contract must be plain. Refinements (including field, payload and container element refinements), opaque metadata, generics and preconditions are excluded. Fixed positional/keyword signatures and supported immutable literal defaults retain the ordinary binding rules; mutable defaults are excluded. Loops, container writes, erased proof calls, other decorators, async execution, mutually recursive dependencies, unreflected or trusted external calls are excluded. Existing scalar operations, product/list/dictionary construction, product operations, list concatenation/slicing, optional tests/projections, mapping membership and get, immutable constants, conditional expressions and calls to other reflected functions are admitted. Indexing and variable division are permitted only when independent raw-body verification establishes definedness on every evaluated path over the entire plain input domain. A guarded lookup or optional projection can therefore be reflected; a precondition cannot supply an unconditional logical equation. Supported string operations use the content model below.

Compile the acyclic definition to a logical expression over formal parameter IDs, then substitute actuals simultaneously. Statement bodies reuse ordinary source typing and CFG lowering. Symbolic block expressions preserve parallel unpacking, branch joins and early returns. Checks are not assumed as premises; source-body verification must discharge assertions, local contracts and unused partial computations independently. Memoized block templates and incremental size/depth limits bound substitution before publishing a definition. In bodies, annotations, assertions, requires, and loop invariants, a reflected call uses this exact expression. Evaluate all written arguments in source order, even when a formal is unused; argument definedness remains an obligation under the enclosing short-circuit guards. Source dependency verification gates caller proofs even when a reflected expression simplifies to a tautology or its result is unused. Loop-free acyclic definitions terminate when their reflected dependencies do; raw-body checks establish safety without assuming declared postconditions. Direct recursive definitions require the additional admission checks below.

Reject reflection dependency chains deeper than 32 definitions and expanded definition terms whose serialized representation exceeds 128 KiB, or statement CFG expansion deeper than 128 edges, with unsupported. Never install a partial definition. Resolved definition sources participate in dependency checks and cache identity. Regular imports/re-exports are supported; annotation-only imports do not establish runtime definitions.

A lemma is an ordinary checked function, often returning refined None. Calling it uses its verified normal-return contract. No special lemma directive or unchecked axiom is added. Restricted well-founded induction is supported through recursive contracts and checked integer descent, as described below. Ordinary functions, including lemma functions, retain the partial-correctness guarantee; a lemma call only establishes its postcondition on paths where it returns. Recursive user-defined data types remain unsupported. List-content equations are supported for admitted nonrecursive definitions: append(xs, ys) can return xs + ys, and reverse(xs) can return xs[::-1]. Their reverse/append equation, concatenation identity and associativity can be checked without recursive logical axioms. Recursive reflection is described below.

Recursive reflection

A reflected definition may call itself by its declaration name when all inputs and the result use plain supported value types, including fixed products, optionals and supported containers. It has a loop-free body, no refinements or preconditions, and only whitelisted operations and reflected non-self callees. Indexing is admitted only after raw-body safety checks prove its path-dependent definedness. An explicit integer decreases decorator is required:

import refinepy
@refinepy.reflect
@refinepy.decreases(lambda n: max(n, 0))
def count(n: int) -> int:
    return 0 if n <= 0 else 1 + count(n - 1)

def bounded(n: Annotated[int, Refine(lambda v: 0 <= v <= 7)]) -> Annotated[
    None, Refine(lambda _, n: count(n) == n)
]:
    return None

The frontend compiles a template with symbolic self-applications. Compilation is provisional: the driver checks the source body with raw self-calls, then checks integer descent with all call-result contracts removed. All non-self source dependencies must independently verify and terminate. No caller proof query can use the template until that dependency verification succeeds. A failed, unsupported or uncertain measure blocks even reflexive equations such as count(n) == count(n) and prevents successful cache entries. The definition’s own equations cannot remove its self-call obligations or justify its termination.

Recursive reflected calls use a canonical typed uninterpreted application, so a goal and a recursive lemma’s hypothesis refer to the same logical function. After independent source admission, the driver adds finite ground instances of its one-step definition for applications appearing in each query. Default bounds are up to eight layers for scalar-only signatures and three if any input or result contains a container, including inside a product or optional. Queries for a recursive refined-None lemma carrying decreases use one-step equations; its explicit self-call contract supplies the induction hypothesis. No universally quantified recursive defining axiom is installed.

Defining equations use recursive source-value equality: scalar values compare normally, optional tags guard payload comparisons, and product fields compare recursively. Sequence snapshots equate length and valid elements; mapping snapshots equate domains and values at present keys. Padding remains unconstrained. Guard each equation by source-domain validity of every argument, including nonnegative sequence lengths and valid string contents in nested fields and container elements. For valid arguments, the equation also guarantees result validity. Internal snapshots outside this domain cannot justify equations. Worker protocol v13 introduces internal ValueEqual and ValueValid terms with matching sort checks, substitution, SMT encoding and concrete replay. ValueEqual requires both values to be valid and compares only observable contents; invalid comparisons totalize to false. It retains each operand once in the serialized equation, avoiding duplicate expansion of large calls. These terms do not add source equality operators for mappings or abstract sequences. Lambda array arguments receive fresh internal array names with exact full-domain pointwise equations. SSA snapshot equalities involving lambdas in UF queries also use full-domain pointwise equality, not source list equality. These aliases carry no added length, element or snapshot-domain assumptions. Aliases and ground applications under local map/element binders never escape their scope; scoped applications receive no additional defining equations in this implementation.

Each query admits at most 64 defining equations and 128 KiB of serialized ground equations. If the default expansion exceeds that budget, retry with one layer. Exceeding the budget at one layer returns unknown with analysis-limit. Reducing optional equation expansion weakens the proof context; every mandatory source obligation still requires an unsatisfiable query. The 128 KiB stored-definition and acyclic-expansion bound and 32-definition dependency bound remain unchanged. Recursive bounded-expansion admission preflight has a separate 4 MiB serialized-term budget, checked after each substitution and assembled result; exceeding it produces unsupported. Its expanded term is discarded, so increasing that preflight budget supplies no additional equations or proof assumptions. This admits the ordinary two-branch Fibonacci recurrence; examples/fibonacci/README.md describes the checked addition lemma and its direct specialization to doubling identities in pair. Mutual recursion, self-calls through aliases and configurable unfolding depth remain unsupported.

Satisfiable worker queries containing applications return unknown: function interpretations are not reconstructed as source witnesses. This includes some false equations with small arguments. Unsatisfiable queries prove obligations for the actual interpretation too. Without an explicit inductive lemma, unbounded equations may remain inconclusive. Nonrecursive reflection retains its exact expression semantics. Entry inhabitation has a separate bounded witness check described under results; it supplies no universal equation or proof of a postcondition.

Successful recursive admission adds reflection:<identity>:verified recursive definition; unfolding depth=<depth>; residual calls uninterpreted together with the definition’s verified termination: evidence. Both propagate through checked dependencies and cache hits. <depth> is 8 for scalar-only signatures and 3 for list signatures. Worker protocol v9 extends typed application terms to list arguments and results. Flatten list inputs to length and contents; list results use separate length and contents functions with the same complete argument tuple. Only the admitted ground equations constrain them; no global recursive defining axiom or independent result-domain fact is assumed. Their interpretation over full input snapshots need not respect source list-content equality; this loses proofs but includes the actual interpretation. Signature consistency checks and encoded source identities remain required; old protocol versions are rejected. Report schema v3 is unchanged.

No annotation execution

Predicate language and definedness

Predicates support literals, permitted binders, integer addition, subtraction and multiplication (including variable operands), integer division/modulo with proved nonzero divisors, comparisons, short-circuit operand selection and conditional expressions, length, sequence indexing, and mapping membership, lookup, and get. Their result must be bool. Arbitrary Python calls, unreflected user-defined predicate functions, I/O, mutable globals, and explicit quantifier syntax are outside the predicate language. Explicitly reflected functions over supported value types are admitted as described above.

Comparison chains evaluate shared middle operands once and short-circuit. Chains containing None, in or not in are unsupported; express these tests as separate boolean guards instead. For example, use left is None and right is None or key == "x" and "x" in table.

Scalar, None, list literals with supported elements and fixed-tuple construction are permitted; dictionary construction is body-only. Predicates may concatenate fixed tuples, take their static slices, read a field at a literal integer index and use the supported optional tag tests. Tuple construction evaluates every field even when equality has a statically known result or a subsequent slice is empty; all field definedness obligations remain required. Lexically resolved immutable constants may be substituted, but arbitrary global reads remain unsupported.

A body-level function call can be checked through a contract without making that function available inside logical predicates. Explicit reflection supplies a pure, total, terminating interpretation for the restricted definitions above; ordinary or trusted call contracts do not.

Lower an expression into both its value and its condition for evaluation without a modeled error:

lower(e) = (V(e), D(e))

D(p and q) = D(p) ∧ (V(p) ⇒ D(q))
D(p or q)  = D(p) ∧ (¬V(p) ⇒ D(q))
D(a if c else b)
            = D(c) ∧ (V(c) ⇒ D(a)) ∧ (¬V(c) ⇒ D(b))

Here p and q have bool type; c is the result of the supported truth conversion. For non-bool operands, replace V(p) in the definedness guards with its typed truth conversion. The value is the selected operand, not a boolean: V(a and b) = ite(truth(V(a)), V(b), V(a)) and V(a or b) = ite(truth(V(a)), V(a), V(b)), with result coercions to the compatible joined type. Evaluate a once and evaluate b only on the selected path. Chained comparisons evaluate intermediate operands once and short-circuit. See Python expression semantics.

Truth conversion and optional narrowing

Lower conditions in if, while, conditional expressions, and assert, and the operand of not, through a typed truth operation. Supported conversions are bool identity, integer nonzero, nonempty string/list/sequence, fixed tuple arity, and false for None. An optional is false when absent and otherwise uses its payload’s supported conversion. Mapping truth and user-defined truth methods remain unsupported. Reject an optional truth test if its payload has no supported truth operation.

A false truth test on Optional[int] permits both absence and a present zero, so it must not narrow directly to None. Equality against None is also a tag test in the exact modeled domain. Other optional operations require prior narrowing.

Reassignment and evaluation order

Core representation

The following is IR notation, not an executable language implementation.

atom       ::= literal | ValueId
rhs        ::= primitive(atom*) | call(FunctionId, atom*)
statement  ::= let ValueId : BaseTy = rhs
             | check BoolTerm Origin
terminator ::= return atom
             | jump BlockId(atom*)
             | branch atom BlockId(atom*) BlockId(atom*)
block      ::= BlockId(parameters*) { statement* ; terminator }

Name every non-atomic operand with a let. Never hoist a short-circuit operand or an unselected conditional branch across its controlling branch. check denotes a static proof obligation, not an inserted runtime check.

Replace φ-nodes with block parameters and edge arguments. A loop is a continuation with a back edge, checked using the same parameter-passing discipline. This first-order representation does not require general higher-order functions or unrestricted recursion.

Join scope and relational refinements

def correlated(flag: bool) -> Annotated[int, Refine(lambda r: r == 1)]:
    if flag:
        x = 0
        y = 1
    else:
        x = 1
        y = 2
    return y - x
then: jump join(0, 1)
else: jump join(1, 2)
join(xj, yj):
    # Entry relation: κ_join(xj, yj, flag0)
    let r = sub(yj, xj)
    return r

Independent intervals 0 ≤ xj ≤ 1 and 1 ≤ yj ≤ 2 lose the needed relation yj = xj + 1. Use one relational predicate over the block environment, together with element refinements where applicable.

For block B, declare κ_B(P_B, C_B):

  • P_B contains its SSA parameters, bound simultaneously so that predicates can relate them.
  • C_B contains immutable values available at block entry: function-entry values and dominating definitions needed by contracts, qualifiers, or subsequent checking.
  • A value defined on only one incoming edge is not a capture. Pass it as a block argument if the continuation needs it.
  • At a loop header, distinguish invariant captures from values passed anew on each iteration. Never capture a changing iteration value as an outer constant.

Retain captures conservatively so every dependency remains in scope. A qualifier’s free variables must be a subset of P_B ∪ C_B. Definitions made later in the block are not in the entry predicate’s scope.

For edge E → B, generate:

Γ_E ∧ edge_guard ⇒ κ_B(actuals_E, captures_E)

Substitute all arguments simultaneously. Edge-local names may occur inside that constraint, but cannot remain free in the solution for κ_B. Semantically, the solution overapproximates reachable entry states after forgetting those local names.

Do not conjoin the assumptions from mutually exclusive incoming paths at a join. Doing so can introduce contradictions and prove invalid obligations vacuously.

Loop example

def count_to(n: Nat) -> Annotated[int, Refine(lambda result, n: result == n)]:
    i = 0
    while i < n:
        i = i + 1
    return i
entry(n0):
    jump loop(0)
loop(ih):
    let c = lt(ih, n0)
    branch c body(ih) exit(ih)
body(ib):
    let inext = add(ib, 1)
    jump loop(inext)
exit(ie):
    return ie

Place κ_loop(ih, n0) at the loop header. Its essential constraints are:

Initiation:   n0 ≥ 0 ⇒ κ_loop(0, n0)
Preservation: κ_loop(i, n0) ∧ i < n0 ⇒ κ_loop(i + 1, n0)
Exit:         κ_loop(i, n0) ∧ ¬(i < n0) ⇒ i = n0

One solution is 0 ≤ i ∧ i ≤ n0. The stronger condition i < n0 is not a header invariant: it fails for n0 = 0 and on the final back edge. Keep a body guard distinct from an invariant at the point where that guard is evaluated.

A continue generates another header preservation obligation. A break generates an exit edge without the negated loop guard. An early return checks the function’s return contract at that location. Nested loops receive separate predicates; solve the constraint dependency graph by components including its back edges.

Supported for loops

Accept iteration over a stable modeled list or homogeneous tuple, and direct range(stop), range(start, stop), or range(start, stop, step) in the iterable position, each with a single name target. Also accept direct enumerate(sequence) and enumerate(sequence, start) with a flat pair-of-names target. Range and enumerate are intrinsic loop forms, not first-class iterator values; iter, next, zip, arbitrary iterables, and iteration over strings or mappings remain unsupported.

Evaluate the iterable and its arguments once. Capture that snapshot even if the source variable is rebound in the body. Introduce hidden progress variables separate from the source loop target. For a sequence, check an internal index against its captured length, read the element, assign the source target, and enter the body. For a range, start at start, require step != 0, test < stop for positive steps or > stop for negative steps, and advance by the fixed captured step. Do not call Python len(range) or approximate arbitrary ranges with finite unrolling.

For enumerate, keep both sequence progress and the external counter; produce the current pair before incrementing. Reassigning the source target or counter does not change hidden progress. Normal exhaustion retains the last source target value; a zero-trip loop performs no target assignment. Apply conservative definite-assignment checking to reads after the loop rather than inventing a last value. break, continue, early return, and else use distinct CFG edges. User hints and inferred predicates are checked through the same ANF loop machinery. See Python for semantics.

Lowering advances hidden progress before the body so every continue carries the next state; this is unobservable within the stable intrinsic model. Source target writes still follow Python order, including repeated names and local contracts. Hidden state is passed explicitly through body joins and nested loops, and the exhausted loop drops its private state before else while preserving enclosing state. Range definedness requires a nonzero step even for an empty range.

Calls and trusted contracts

Argument evaluation and binding

Support positional arguments, explicit keyword arguments, positional-only parameters, keyword-only parameters, and defaults that are supported scalar/None literals or flat tuples of int/bool/str literals. Signed integer literals are included; reject nested-tuple defaults, tuple defaults containing None, other computed default expressions, mutable defaults, variadic parameters, and */** expansion. A single defining function has a fixed known signature. Recognize a qualified call such as module.helper(...) only when static import resolution fixes that exact function; it is not general attribute evaluation. Callable aliases and general overload dispatch remain unsupported.

Evaluate call operands in their Python source order before arranging values into formal-parameter order. Then bind explicit arguments, reject missing/duplicate/invalid keywords, fill omitted arguments from definition-time default values, and simultaneously substitute the bound values into contracts. Literal defaults are not recomputed at each call. Their base types are checked at definition; dependent refinements are checked at each actual call, since they may depend on other arguments. At a generic definition, defaults must be valid for every admitted specialization. See Python calls.

Every external callable must have an explicitly selected model. A registry record has these required fields:

For binding, requires and definedness use the function-decorator convention: every lambda parameter names an entry input. ensures uses the return-annotation convention: its first binder is the result and later binders name entry inputs. At a modeled call, prove both the instantiated precondition and the declared operation-definedness condition. Only then apply the normal postcondition on the call’s normal-return edge. Neither field is an unchecked assumption at a checked call site. Omission, schema-version mismatch, or a model/runtime version mismatch is an error; never fall back to a base-type stub.

Dependencies have distinct origins: verified-body, trusted-model, or unresolved. A trusted model may establish a call’s contract, but its identity remains in dependency results and its initializer assumptions are retained internally. A stub-only signature, an unchecked source annotation, or a user cast cannot establish purity or preserve snapshot facts. unresolved blocks verification, and model changes invalidate all dependent results.

Refinement checking and Liquid inference

Types and obligations

Write a basic refinement as {ν : B | p}. For equal base types:

Γ ⊢ {ν : B | p} <: {ν : B | q}
    iff Γ ∧ p ⇒ q

Z3 query: Γ ∧ p ∧ ¬q
An unsat result establishes the implication under these assumptions.

Add binding equalities, path guards, established element invariants, and verified callee postconditions to the environment. Base-type mismatches are not resolved by SMT implication alone.

At a call, evaluate arguments in order, substitute dependent parameters simultaneously, and prove the preconditions. Use the postcondition only after the callee has been verified or explicitly registered as a trusted specification, except for the direct self-call hypothesis below. Check dependencies between distinct functions in acyclic order. A failed or unsupported callee cannot leave its callers reported as verified.

Direct recursion

A body call resolving to the current function’s canonical identity may use that function’s explicitly annotated parameter and return contracts as a local partial-correctness hypothesis. Plain base annotations are valid contracts with no additional predicate; no recursive contract is inferred. Check argument refinements, function preconditions, predicate definedness, modeled safety and all normal returns using the existing call and body rules. Entry contracts must still be inhabited. For finite scalar generics, every declared specialization must verify before the function succeeds.

The justification is induction on finite returning executions, not an assumption that recursion terminates. No decreasing measure or reachable base case is required. A function that only calls itself can satisfy even an impossible return predicate because it has no normal return in the modeled execution. This contract rule does not supply a logical interpretation of recursive calls or treat divergence as a logical value. Explicit reflection requires the separate safety and termination admission checks above.

Do not publish a provisional self-contract as a verified dependency or cache entry. External callers may use it only after every required body obligation, specialization and other dependency succeeds. A cycle through distinct source functions remains unsupported, even if it also contains a direct self-call. Reports retain a direct-recursion: dependency-evidence entry stating whether integer descent has been checked; otherwise termination and recursion depth are not verified. This evidence propagates to callers. Python recursion-depth exhaustion remains outside the runtime model.

Decreasing measures

A @refinepy.decreases(lambda n: n) decorator requests termination checking for the decorated top-level function. Its lambda binds only named entry inputs and must return plain int or a literal nonempty fixed tuple of plain integer components, using the same logical purity and binder restrictions as predicates. The measure must be defined under the entry contracts and preconditions. It is evaluated logically, never by executing source Python.

import refinepy
from refinepy import Refine
from typing import Annotated

Nat = Annotated[int, Refine(lambda v: v >= 0)]

@refinepy.decreases(lambda n: n)
def count(n: Nat) -> Annotated[int, Refine(lambda r, n: r == n)]:
    return 0 if n == 0 else 1 + count(n - 1)

For every direct self-call, bind all actual arguments simultaneously using the ordinary positional/keyword/default rules. Prove measure definedness on those actuals and strict lexicographic descent under the call’s path condition. Every component of both the entry and next measure must be nonnegative at a self-call. For a scalar this is equivalent to 0 <= next_measure < entry_measure. A tuple compares the first unequal component: (n - 1, 3) is smaller than (n, 0) when n > 0. Later components may increase or reset but must remain nonnegative; unrestricted integer lexicographic order is not well-founded. Empty tuples, nested tuples, boolean components and dynamically constructed measures are annotation errors. A one-component tuple has scalar descent semantics. The current measure refers to immutable entry inputs, even when body locals have been reassigned. A base path without a self-call need not have a nonnegative measure. Measures such as max(n, 0) and len(xs) are admitted.

@refinepy.decreases(lambda n, m: (n, m))
def lex_count(n: Nat, m: Nat) -> int:
    if m > 0:
        return lex_count(n, m - 1)
    if n > 0:
        return lex_count(n - 1, 3)
    return 0

Every loop in a termination-checked closure must have an explicit preceding decreases(lambda ...) call. Its binders name definitely bound source header locals, not immutable function inputs or hidden iterator counters. On each taken iteration, prove definedness and nonnegativity of all components, then snapshot their values before executing the body (and before binding a for target). On every fallthrough or continue back edge, prove definedness, nonnegativity and strict lexicographic decrease against that snapshot. Snapshots cross joins and nested loops as explicit SSA arguments; they cannot capture changing locals as constants. No decrease is required on break, return or a failed header guard. The next measure must be defined and nonnegative even on the final back edge; use a total measure such as max(n - i, 0) if the raw expression would become negative. An initially unbound for target cannot occur in the measure. Loop invariants establish the induction over iterations through checked initiation and preservation; an invariant alone supplies no termination evidence.

All other source callees must independently carry verified termination evidence. Trusted model contracts do not establish termination. Mutual recursion remains unsupported. Missing loop measures, including in syntactically unreachable loops, prevent a requested termination proof. These restrictions also apply to functions carrying a measure but no self-call. Nonrecursive functions with all loops measured (or no loops) automatically acquire termination evidence after all checks when their complete call closure terminates. Functions without sufficient measures retain partial correctness and publish no termination evidence.

After ordinary safety and contract verification, check a separate copy of the CFG with every call-result summary and every non-termination check removed. Preserve exact SSA definitions, guards and entry contracts. Application-free fixed loop invariants retain their definedness and must establish initiation and every preservation edge again without call summaries. For a header with application-bearing hints, retain only application-free conjuncts that contain no partial read, optional projection, variable division or scoped map/element predicate. Check these weaker, syntactically total hints independently; the complete source invariants remain mandatory in ordinary verification. Reports distinguish this termination projection from user-supplied hints. Ordinary contract verification cannot justify descent in this independent proof. This prevents a provisional recursive postcondition, including an impossible one, from making descent vacuous. Call results remain unconstrained; this deliberately conservative proof may fail when descent depends on a call’s result contract. Every finite generic specialization must pass. Solver uncertainty or an unmet obligation prevents success, and no termination evidence is published before all checks pass.

Reports record termination:<identity>:verified; recursion depth and resource exhaustion are not verified, as well as termination-measure-definedness and termination-decrease obligation kinds for recursive measures. Loops add termination-loop-measure-definedness, termination-loop-nonnegative and termination-loop-decrease obligations; early-exit-only bodies have no back-edge decrease obligation. Evidence propagates through dependencies and cache hits; source and measure edits invalidate reuse. This proves mathematical termination under the modeled execution assumptions, not freedom from Python recursion-depth limits or resource exhaustion. It does not by itself supply reflected equations. When combined with a verified recursive refined-None return contract, it supplies the well-founded induction rule below.

Inductive lemma functions

A recursive ordinary function returning refined None can prove its return proposition by well-founded induction when it carries an explicit decreases measure. No lemma or induction directive is needed. Use the normal self-call contract as the induction hypothesis only after checking its arguments and preconditions; every base and recursive return must establish the declared proposition. Independent summary-free descent checks must prove a nonnegative strictly smaller measure at every self-call. All dependencies must verify and terminate. Any loops must carry independently checked measures; mutual recursion remains unsupported.

The reflected functions mentioned in the proposition are admitted separately; the lemma cannot justify their safety or termination. Canonical applications and one-step ground equations align the recursive definition with the self-call hypothesis. Explicit returns in each branch avoid needing qualifier inference at a join; joining branches can still be inconclusive. Solver uncertainty, incorrect bases, missing hypotheses or failed descent do not publish a theorem.

Successful checks add induction:<identity>:verified return proposition; checked integer descent at every self-call alongside termination evidence. Both propagate to callers and cache hits. Ordinary source callers use the proved normal-return contract as usual; the inductive lemma itself has additional mathematical termination evidence. Functions without a measure retain partial correctness, including potentially divergent lemma functions, and receive no induction evidence. This is a restricted proof-by-recursive-function facility, not automatic induction search, an explicit quantifier language or support for arbitrary inductive data types.

Qualifiers

Liquid Types combines finite logical qualifiers with predicate abstraction. Following that approach, represent each unknown predicate as a conjunction of well-sorted candidates in its scope. See Liquid Types.

Do not automatically instantiate application-bearing qualifier templates; recursive specification invariants must be explicit. Optional qualifier checks discard application-bearing antecedent conjuncts, proving candidates in a weaker context so worker models need no residual function interpretations. Spurious models can remove useful candidates but cannot establish a source violation. Final Horn edges, fixed invariants and source obligations retain the full facts and independently require unsatisfiable queries.

Candidate examples:
    a ≥ 0
    a ≤ b
    a = b + 1
    len(s) > 0
    key ∈ dom(m)

κ_B(args) = ∧ { q(args) | q ∈ S_B }

Use built-in templates plus expressions and constants extracted from contracts, guards, and supported arithmetic assignments. Instantiate only sort-compatible variables within the declaration’s scope. Candidate generation must include i ≥ 0 and i ≤ n0 for count_to, and yj = xj + 1 for correlated.

User-defined qualifier templates are unsupported; the checked invariant directives above provide proof-recovery input. Expose candidates and inferred predicates when a proof fails.

Generate candidates deterministically: seed linear equality/order and nonnegative templates, extract admitted boolean subexpressions from contracts/guards/hints and normalized arithmetic binding equalities, then instantiate compatible in-scope variables in stable ID order. Use constants -1, 0, 1 plus distinct integer literals in the target and its contracts. Do not invent unbounded arithmetic combinations. Built-in templates have at most three variable positions; explicitly supplied invariants are not subject to that template-arity restriction.

Require all candidate variables to be in scope and all terms to be well-sorted. A candidate containing a partial read must prove definedness from its own short-circuit guards and established base/element facts, without assuming the candidate itself. Otherwise do not admit it as a qualifier; report the rejection if it originated from an explicit contract or hint. A fixed user invariant may additionally use other established loop facts, but its own definedness remains a checked obligation.

Configurable resource defaults are 2,048 candidate instances per unknown predicate, 16,384 per target, 32 distinct extracted integer constants in addition to the three seeds, 2 seconds per SMT query, and 60 seconds per target. These are policy limits, not measured performance guarantees. Exceeding a generation limit stops that target with unknown: candidate-limit; do not silently truncate and present a complete search. A solver timeout while testing a candidate may still weaken it as described below; a final success requires all obligations rechecked successfully and records the lost candidate.

Solving constraints

Use Horn constraints whose antecedents contain background-theory formulas and positive applications of unknown predicates, and whose head is one unknown predicate or a concrete obligation. Do not generate negative occurrences of unknown predicates or higher-order predicate expressions.

  1. Initialize each S_B to all candidates applicable to κ_B.
  2. For each defining constraint A ⇒ κ_B(t) and candidate q(t), ask whether A ⇒ q(t) holds under the current solutions.
  3. Remove a candidate unless the query establishes validity with unsat. Removing a candidate weakens κ_B. If a query returns unknown, record that a potentially useful candidate was lost because it could not be established.
  4. Whenever a solution changes, revisit constraints that use that unknown predicate in their antecedents. Continue until stable.
  5. Substitute the stable solution into every constraint, including concrete safety obligations, and recheck them. Verification succeeds only if every required final implication is established.

The candidate iteration terminates because it only removes members of finite sets. SMT queries require their own limits. Never reuse a proof obtained under an older, stronger inferred antecedent after that antecedent has been weakened. Explicit user contracts are fixed obligations, not candidates the solver may weaken.

A sat result for a final safety query can mean that the inferred invariant is too weak. Since these invariants overapproximate reachability, it is not automatically a program bug. Report an unproved obligation and the inferred invariant unless a concrete execution correspondence is established.

Use the ordinary Z3 solver as an implication oracle. Each generated Horn clause has at most one positive source relation in its antecedent. Exact paths remain separate; a defensive ceiling of 100,000 clauses returns unknown: analysis-limit. Candidate queries may batch implications: a validated countermodel removes every falsified candidate before the edge is revisited. Weakening increments the solution version and reschedules dependent checks. No successful implication survives a change to its antecedent solution version.

Logical models

Integers and booleans

Model Python integer values with mathematical integers and SMT Int. Preserve literals using an arbitrary-precision Rust representation, not i64. Use logical Bool for booleans and insert ite(b, 1, 0) where a bool is used as an integer.

Unary plus and minus return integers. Numeric arithmetic and comparisons, including mixed bool/int equality, apply this embedding before the operation. Bool-to-bool equality may stay in Bool; it must agree with the numeric interpretation. No integer-to-bool subtype conversion is inferred. Unrelated scalar domains cannot be compared through an arbitrary SMT sort cast; mixed numeric/string comparisons are rejected in this subset.

Respect ordinary Python typing in which a bool can be accepted as an int. Type reflection such as type(x) is int is unsupported, so the model need only preserve the supported numeric observations. See Python numeric types and bool.

Support integer a * b and a * a with variable operands in bodies and predicates, including *= with a variable RHS. Encode products exactly as SMT integer multiplication and evaluate concrete models using arbitrary-precision integer multiplication. Preserve bool numeric embedding and check declared local contracts after augmented rebinding. Nonlinear integer arithmetic is admitted without a completeness guarantee: solver uncertainty and resource limits remain unknown, never a successful proof. The existing multiplication term and worker protocol already represent these products; no protocol change is required.

Support a // b and a % b for signed integer operands in bodies and predicates, including augmented rebinding. Evaluate both operands once in source order and prove b != 0 before admitting source evaluation. Predicate definedness retains the same guard, including short-circuit contexts, annotations, invariants and call contracts. Statically zero divisors remain unsupported. Bool operands use numeric embedding, so a boolean divisor requires proof that it is true. Signed literals, immutable constants and closed supported expressions keep the existing constant-divisor lowering; local variables use dynamic lowering even when assigned a literal. Variable-divisor and nonlinear proof uncertainty is unknown, never a successful verification.

For positive c, encode the quotient as SMT integer div(a, c). For negative c, encode div(-a, -c) so the SMT divisor stays positive and the result is Python’s floor quotient. Encode the remainder as a - (a // c) * c. Preserve arbitrary precision, negative dividends, exact multiples, and unit divisors. The logical evaluator uses floor rounding, not truncation toward zero. Worker protocol v5 adds a floor-division term whose divisor must be a canonical positive integer; validate it before SMT rendering.

Worker protocol v10 adds the binary FloorDivBy term, with two integer children. Its SMT encoding selects div(a,b) for positive b, div(-a,-b) for negative b, and zero for b == 0. The concrete evaluator agrees at arbitrary precision. Zero totalization is internal only: independent nonzero definedness obligations prevent any successful source evaluation from using it. Modulo is lowered as a - FloorDivBy(a,b) * b, preserving the divisor’s sign. Sort checking, substitution, traversal and reflected equation expansion retain both operands. Dynamic division and indexing in acyclic or recursive reflection require raw-body safety admission. Report schema v3 is unchanged; old workers are rejected.

Strings

Keep the logical str type separate from its SMT representation. Worker protocol v16 encodes Python strings as (Seq Int): each valid position holds a code point between 0 and 0x10FFFF, including surrogates. Literals retain Vec<u32> contents. Equality compares complete sequences; length uses seq.len. Empty strings and equal-length strings follow the native sequence theory without opaque identity or length-function axioms.

Support string concatenation, integer indexing and step-1 slicing in bodies and predicates, including reflected total definitions. Concatenation uses seq.++; local string += rebinds through the same operation. Indexing proves -len(s) <= i < len(s), normalizes a negative index to len(s)+i, and uses seq.at; the result is a string of length one. The solver’s empty result for an invalid index never establishes a safe Python read. Boolean indices and bounds use the existing integer embedding.

Slices reuse Python list-bound normalization: integer, omitted and literal None bounds, negative offsets and clipping. The step is omitted, None or a statically known integer equal to one. Lower normalized start and length through seq.extract. Evaluate written operands once in source order; an empty slice still checks the receiver’s definedness. Negative or other steps, iteration, search, methods, formatting and regular expressions remain unsupported.

Worker protocol v17 admits string <, <=, > and >=. Order is lexicographic over integer code points: a proper prefix is smaller, otherwise the first unequal code point determines the result. Encode strict order using prefix extraction/equality and an existential in-bounds differing position; non-strict order negates the reversed strict order. Concrete witness replay uses the same complete code-point order. This is case-sensitive and performs no locale comparison or Unicode normalization. Quantified proof uncertainty remains unknown; string order is not a solver completeness guarantee.

Mapping arrays use (Seq Int) keys so computed strings and literal keys share content equality. Worker snapshots serialize exact string keys with the existing injective integer code-point encoding; this encoding is a transport key, never a source-observable carrier. String-keyed lambda arrays cannot use the integer cutpoint decoder and produce unknown unless reconstructed as constant/store arrays. List arrays containing strings retain integer positions.

Model reconstruction reads every string code point and returns concrete Str values. A string is limited to 4,096 decoded code points, within the shared structural reconstruction budget; exceeding the limit yields unknown, never a truncated witness. Parent validation rejects legacy abstract-string evidence and checks all concrete contents and exact query assertions. Solver uncertainty is preserved: native sequence operations do not guarantee that arbitrary identities, such as splitting and rejoining at a symbolic clipped boundary, finish within the query timeout.

SMT-LIB’s Strings theory uses code points through 0x2FFFF, whereas Python’s chr accepts values through 0x10FFFF. Rust char excludes surrogates. Preserve Python string literals in a code-point representation such as Vec<u32>. See SMT-LIB Unicode Strings, Python chr, and Rust char.

Sequences and lists

Represent a sequence snapshot as (length, elements), with length: Int, elements: Array[Int, ElemSort], and length ≥ 0. Support built-in lists and built-in tuples with supported elements received through a Sequence interface. Do not assign this model to range or arbitrary user implementations.

Model negative indices explicitly:

L = length(xs)
D(xs[i]) = D(xs) ∧ D(i) ∧ (-L ≤ i ∧ i < L)
j = ite(i < 0, L + i, i)
V(xs[i]) = select(elements(xs), j)

The array’s out-of-range values never justify a successful read.

The meaning of Sequence[Nat] requires every valid element to be nonnegative. Implement that discipline through three rules:

  • Retain evidence for element refinements from an input contract or a verified producer, attached to the same snapshot.
  • Instantiate the element refinement at a proved-safe read.
  • Check every element when constructing a literal. Strengthening an existing sequence’s element type requires a general justification, such as element subtyping, rather than sampled reads.

Observing a few nonnegative elements does not establish Sequence[Nat]. Scalar-element list and fixed tuple literals are supported; simple list comprehensions and certified exclusive local list writes are also supported. Contextual types resolve empty lists. A fixed tuple can supply a homogeneous Sequence[T] view only after every field is checked as a subtype of T. Empty fixed tuples require a typed sequence view because no element sort can be inferred.

Attach element evidence as a closed unary Every predicate universally guarded by the snapshot’s valid domain. Writable element contracts use an alpha-normalized predicate key: invariant conversion requires equal keys and element base types. This is a conservative syntactic equivalence check; it does not decide general logical equivalence. Read-interface strengthening uses proof obligations.

Bind the element symbol lexically inside the domain quantifier. Nested logical map binders retain their own identities, even when their generated names share a prefix. String observations from the predicate stay inside the same binding; textual substitution of rendered symbol names is not a valid implementation.

Use covariance for the read interface Sequence[T] and invariance for list[T]. The ownership restriction on writes does not redefine normal list variance. A list[Nat] can provide a Sequence[int] view after establishing element subtyping. See typing variance rules.

List content equality and concatenation

Built-in list[T] snapshots support == and != in bodies and predicates when both operands have the same recursively comparable element sort. Element-contract keys may differ: observing content equality does not transfer a writable contract. Concatenation + additionally requires matching element-contract keys. Abstract Sequence receivers, mappings, heterogeneous element comparisons, list ordering and identity tests remain unsupported. Evaluate written operands once in source order, including unused reflected arguments.

Comparable elements recursively comprise scalars, None, optionals, fixed products and built-in lists. An abstract Sequence or mapping anywhere in the element type blocks source equality; content snapshots cannot distinguish a list from a tuple received through a Sequence interface. This restriction also applies to lists nested inside product equality.

Python list equality means equal lengths and equal elements at every index 0 <= i < length. Ignore the internal array outside that domain. Keep this logical ListEqual operation separate from internal full-snapshot Equal, which still constrains SSA values, including their array representation. Do not infer equal internal arrays from equal source lists.

Concatenation has length len(left) + len(right). Its valid index i reads left[i] when i < len(left), otherwise right[i - len(left)]. The result uses the structural default outside its valid domain. Matching element-contract keys preserve refined element evidence; incompatible writable contracts are rejected instead of assigning unchecked evidence to the result.

Worker protocol v7 adds concatenation and domain-guarded list equality terms. Concrete replay compares every partition of the entire valid domain and translates every sparse-array boundary across concatenation, with no length cap or prefix sampling. False quantified equations may remain unproved when a complete source witness cannot be validated; neither unknown nor unproved establishes the equation.

List slices and simple list comprehensions

Body and predicate expressions support xs[start:stop:step] for modeled list[T] values. Evaluate the receiver and written bounds once, in source order. Bounds are integers (including bool embedding), omitted, or literal None; negative bounds are relative to the input length, then clipped to Python’s step-dependent limits. The step is omitted, literal None, or a statically known nonzero integer. For a negative step, an omitted stop differs from an explicit -1. Empty and reversed intervals produce an empty list. Slice writes, variable steps, and abstract Sequence receivers remain unsupported; strings have the separate step-1 model above. Static fixed-tuple slicing is described under None and fixed tuples below.

Normalize a slice to a start a, nonnegative length n, and constant step d. Its valid result element i equals the source element at a + i*d. The new snapshot preserves the source element type and refinements. Integer floor division computes the length without finite unrolling. Internal arrays use the structural default outside the valid result domain.

List comprehensions support [expression for name in source], with exactly one synchronous generator over an existing stable modeled sequence or homogeneous fixed tuple. Evaluate the source once in the outer scope. The target is local to the comprehension and does not change an outer binding. The result is a new list with the source length and a pointwise transformed element array. The expression may yield any supported value type using the pure expression subset. Product, optional, list and dictionary construction, nested single-generator comprehensions, outer values, explicitly reflected calls and admitted intrinsics are allowed. Unreflected source calls, filters, multiple generators in one comprehension, unpacking targets, async generators and direct range iterables are excluded. The iterable expression may itself be a verified source call, slice, or supported comprehension.

Check the element expression’s definedness for every element of the source’s valid domain. Empty inputs do not evaluate that expression; short-circuit guards remain part of its definedness. Contextual result annotations may select the new list’s element type, including nested empty literals, but their refinements still require whole-domain proof. Read-only interfaces retain their element contracts even though their base sorts do not carry invariant refinement keys. Construction checks remain in the element’s logical definedness, including overwritten dictionary entries and expressions whose values are discarded. Reflected dependencies remain attached to the typed map after conversion to logical templates; failed callees block verification even for empty domains or simplified results. List literals, concatenation and slices are also predicate expressions. Empty lists obtain their element sort from a call parameter, result annotation, or adjacent typed list operand. Two untyped empty list operands remain unsupported. Comprehensions remain body-only construction forms.

Worker protocol v6 adds normalized slice and scoped pointwise-map terms. Bound variables stay local during substitution, traversal, and SMT emission. Array-lambda uncertainty during batched candidate inference triggers individual implication checks; only unsat establishes a retained candidate. Uncertainty remains a failure to prove. Concrete replay transforms every sparse-array partition boundary, rather than sampling a prefix or materializing arbitrarily long lists. Both symbolic lengths and replay indices retain arbitrary precision.

Mappings and dictionaries

Use a domain array and a value array:

domain : Array[PyStr, Bool]
values : Array[PyStr, ValueSort]

V(k in m) = select(domain(m), k)
D(m[k])   = D(m) ∧ D(k) ∧ select(domain(m), k)
V(m[k])   = select(values(m), k)

SMT arrays are total maps; a value array alone cannot represent missing keys. See Z3 Arrays.

This abstraction admits infinite domains, but overapproximates the supported membership and lookup observations. Mapping length, mapping equality, key enumeration, and iteration order are unsupported. Adding an unrelated size variable would not establish domain cardinality.

Build mapping literals from an empty domain, evaluate entries left to right, and retain the last value for equal keys. Check value refinements at construction and instantiate them at safe lookups. Mapping is covariant in its value parameter; dict is invariant. Fix the key type to str.

not in is the boolean negation of modeled mapping membership. Sequence membership and substring search remain unsupported. Mapping truth, views, and constructors are unsupported; the presence of array models does not establish these operations.

Admit m.get(key) and m.get(key, default) only on the modeled built-in dict implementations already required by Mapping and dict. The key must be a string. The result joins the element type with the default type using the existing value/optional joins; an omitted default is None. Keyword arguments, expanded arguments, arbitrary receivers and bound method values remain unsupported.

Evaluate the receiver, key and explicit default once in Python order before selecting the result. In particular, a present key does not suppress failures or call obligations in the default expression. Select the mapping value when membership holds and the default otherwise. This conditional lookup has no unconditional key-presence obligation; value refinements follow the selected entry or default. The same pure intrinsic is available in predicates, but its argument expressions must satisfy the predicate restrictions. Static imported functions named get retain ordinary direct-call resolution; local receivers shadow imports.

None and fixed tuples

Use a singleton logical value for None and a tagged sum for optionals. The tag distinguishes an absent value from any payload, including numeric zero. Payload projection has a presence obligation. Function fallthrough uses the same singleton as an explicit return None.

Represent a fixed tuple of supported values by a typed product and its known arity; use tuple[()] for the empty tuple type. Literal construction evaluates fields once from left to right. Support len, flat name-target unpacking of exactly matching arity, and literal integer field indexing with negative-index normalization and bounds checking. Reject dynamic indexing of the product; a homogeneous sequence view can instead use the sequence rules.

Support == and != between fixed tuples in bodies and predicates. Compare scalar fields with bool/int numeric embedding and string content equality, nested products recursively, optional fields by tag and guarded payload equality, and list fields by their valid-domain contents. List element sorts must match; element refinement keys need not match. Mapping/abstract-sequence field equality and mismatched list element sorts are unsupported. Different product arities or unrelated scalar field domains imply inequality. Evaluate both operands once even when the result is statically known. Chained comparisons retain single evaluation of intermediate operands and short-circuit guards. Support fixed-tuple <, <=, > and >= in bodies and predicates. Compare common fields lexicographically: skip equal fields, order the first unequal field, and use the shorter arity when the common prefix is equal. Common fields must pair integers/bools, strings, recursively comparable fixed tuples, or two None values (which always compare equal). Conservatively reject optional, container and incompatible common fields, even if an earlier field could decide the result. Fields beyond the common prefix need no ordering relation. Both products are fully evaluated before comparing; chains still short-circuit between comparisons. Lower products to guarded field equality and order terms. Comparison with a non-tuple (apart from supported None tag tests) remains unsupported.

Support tuple construction, concatenation and slicing in bodies and predicates. Slicing uses statically known integer bounds and a nonzero statically known integer step. Omitted/None bounds and steps use Python defaults; normalize negative indices, clip out-of-range bounds, and distinguish an omitted reverse stop from explicit -1. Select field types statically, including empty results. Evaluate the source once and retain all operand definedness and call obligations even when no fields are selected. Concatenation evaluates left then right once. These operations lower to the existing product/field terms without new solver theories or worker terms. Expected product field types recursively type empty list/dictionary literals in body expressions. Preserve field, optional payload and element refinements at assignments, returns and calls. Writable containers remain invariant inside products; a product cannot hide an alias to a written local list. Returning two locally built lists directly is supported, but storing a reference to either written list in a local product is conservatively rejected. Extracting a list field does not establish fresh ownership. Direct unpacking of a certified isolated source result follows the ownership-transfer rules below.

Worker protocol v12 admits recursive product fields and preserves nested snapshot domain axioms and model validation. Dynamic product slice bounds are unsupported. tuple[T, ...] annotations remain unsupported; homogeneous tuple inputs continue to use Sequence[T].

State and trust boundaries

Read-only verification regions

Sequence and Mapping describe interfaces, not immutable objects. Check that the function and its callees do not modify observed input containers. Rebinding a local reference or constructing a fresh list is permitted. See collections.abc.

def stale_head(
    xs: Annotated[Sequence[int], Refine(lambda v: len(v) > 0)],
    ys: list[int],
) -> int:
    ys.clear()
    return xs[0]

If xs and ys alias the same list, the entry nonemptiness fact no longer holds after clear(). The verifier rejects the write. Distinct parameter names never establish non-aliasing.

Reject unknown external calls, methods, callbacks, attributes, and reflection when their behavior or effects cannot be established. Known calls require transitively checked effect summaries. Fresh container allocation is permitted, but container identity observations and equality on abstract sequences/mappings are unsupported. Absence of concurrent or signal-handler interference and runtime replacement of modeled built-ins are explicit execution assumptions.

Nested container contents are modeled as stable snapshots. An outer allocation does not establish exclusivity of its nested elements; extracting an element cannot justify a write. Input aliases remain conservatively unconstrained because writes to inputs are excluded: the model must allow them to denote the same contents, and must never assume distinctness.

Exclusive local list writes

The frontend admits standalone out.append(value), out.extend(sequence), list out += sequence, and single-target integer out[index] = value when a whole-body ownership certificate establishes an exclusive local built-in list. This extends local result construction without adding a shared-heap model. The certificate is checked before HIR publication and dependency proof use:

  • A written name is never a function parameter. Its ordinary assignments must construct fresh lists through literals, slices, concatenation, comprehensions, conditional expressions with fresh alternatives, or source calls with a checked fresh-list result certificate, under one name.
  • Storing a reference to any written list under another name is rejected, including conditional, optional and Sequence views and potentially aliasing source-call results. This conservative rule covers the whole function, even a reference stored after the last write. A source allocation certificate permits storing an independent result of a call that borrows the written list.
  • Read-only calls may borrow list contents. Every source callee undergoes the same input-write exclusion; trusted calls must retain the declared stable effects. Returning the local list transfers the result at function exit.
  • A loop cannot write a list that may back its captured sequence iterator. Iterating a fresh slice/copy is allowed; iteration without writes in the loop body is allowed even if the list was built earlier or is updated afterwards. Nested control flow is checked conservatively, including syntactically unreachable writes. A written name cannot be an iteration target.

Source result certificates track allocation provenance, not logical content equality. A list result qualifies when every return originates in a fresh construction or another certified source call. A local name qualifies only when every syntactic assignment preserves that provenance; parameters, iteration targets and ordinary unpacked names are conservatively borrowed. Branches and loops cannot hide a borrowed assignment, even if a contract claims it unreachable. Updates retain the receiver’s provenance. Certificates cover all declared generic specializations. Imported and re-exported source callees use their resolved identity.

Certificate discovery starts without freshness hypotheses and propagates only independently derived allocation certificates through an iterative worklist. Thus a recursive function may return an independently allocated concatenation, but a bare recursive result does not establish freshness. Certificate discovery visits at most 64 distinct source functions per discovery; exhaustion declines the certificate, and a write requiring it remains unsupported. Trusted allocates = ["return"] claims do not supply source ownership. Optional and abstract Sequence results do not transfer this certificate. Returning a borrowed list remains supported for read-only use.

A fixed-product source result can carry a stronger isolation certificate. Every reachable mutable container must originate in an allocation, and the reference graphs of distinct product fields must be disjoint. Returning the same list twice, retaining an input, or sharing a nested list across fields prevents this certificate. Allocation-site histories include both branches and all loop trips; unknown alternatives survive field projection and unpacking. Loop-history analysis stops conservatively after 64 rounds without convergence.

A caller may directly consume this certificate with flat unpacking, such as left, right = split(xs), then write either list under the usual exclusive-local rules. Conditional source results require certified alternatives. Imported, reflected and generic source helpers use the same dependency gate; each generic specialization must qualify. Forwarding and returning an unpacked list preserve the applicable certificate. A stored product remains an alias: p = split(xs) followed by left, right = p does not permit writes. Field extraction and nested unpacking do not transfer ownership. Stored aliases and iterator protections remain in force after a transfer. Optional and abstract Sequence results do not transfer ownership through this rule.

Successful reports record ownership:<identity>:isolated-product-result; checked source allocations and disjoint fields only after the complete source dependency closure verifies. The cache retains this evidence and invalidates it when source allocations, sharing or contracts change. Value equality and trusted allocation claims never establish isolation.

For composite elements, freshness certifies only the outer list. Literal construction, append/extend and item replacement must not store references to another written local list, including through products, optionals or source calls. Extracted elements remain borrowed. Shallow copies and composite call results are conservative when their elements could retain a written list reference.

These structural certificates are provisional until every source dependency and its required obligations verify. Failed or uncertain callees block callers and cannot publish ownership evidence. Successful reports record ownership:<identity>:fresh-list-result; checked source allocation and aliases. Element refinements on inferred call results are retained at each subsequent write even when their defining type alias is not imported by the caller. The verified-closure cache includes the defining source bytes and certificate evidence.

Append/extend preserve receiver-before-argument evaluation, once each. Extend and += accept stable modeled sequences and fixed tuples with a common supported element type; a checked pointwise copy supplies a list snapshot when needed. Self-extension uses the pre-update snapshot, matching built-in list behavior. Method values, nested mutation calls, arbitrary iterables, pop, clear, slice writes, augmented item writes, attribute writes and dictionary updates remain unsupported.

Element writes evaluate the RHS before the receiver and index, once each. Check -len(out) <= index < len(out) and normalize negative indices. A store preserves length and all other valid positions. New elements must satisfy their base type and element refinement; inferred copies retain the canonical element contract of their origin. Recheck any declared local whole-list contract after each mutation. Previously observed scalar values retain their old SSA meaning.

ListExtend HIR marks source mutation separately from allocating concatenation; its mathematical value is concatenation of content snapshots. ListUpdate HIR retains RHS-first operands and lowers to an immutable length/array store. Worker protocol v11 adds the typed three-child store term, with matching sort checking, SMT encoding, arbitrary-precision concrete replay, substitution and traversal. Bounds and element contracts are separate checked obligations; a total internal store outside the valid domain never justifies a successful source write. Uncertainty remains a non-success. Report schema v3 is unchanged.

examples/local-lists supplies exact construction, stable filtering, replacement and exchange contracts plus independent finite Python execution checks. The total reflected range_values(n) definition denotes 0 through n - 1 (empty for nonpositive n); even_values(xs) recursively filters the prefix before optionally appending the final even element. Their admitted definitions have independently checked descent. The construction loops retain exact result/prefix equations, with explicit measures. Filter branches return directly to the loop header to preserve those equations without an abstraction join. For arbitrary admitted input lengths, build_range returns exactly the specified range and evens retains every even element in order, including duplicates. replace equates the entire result to the prefix, replacement singleton and suffix at the normalized index, preserving every other position. Python checks compare the specifications with independent range/filter expectations and replace logical definitions with raising sentinels during builder execution. Finite execution checks are separate from the general contracts and checked termination; recursion-depth safety and resource availability remain outside the model.

Model validation and execution witnesses

Worker protocol v6 reconstructs total arrays as constants, finite stores or certified piecewise-constant integer partitions. Lambda certification permits index-independent leaves (including complete array values) and Boolean combinations of comparisons between one index and integer constants. Parallel element arrays are joined on the union of exact stores and region boundaries; region values are assembled without store overrides, then exact stores are assembled with them. Both infinite tails are retained. Reconstruction allows at most 4,096 stores per native array, structural depth 128 and 65,536 decoding steps per query binding; exhaustion returns unknown. Model checking covers every valid partition, mapping default and complete string contents. An unrecognized native array representation returns unknown; sampled contents cannot establish a valid model or a proof.

Worker protocol v14 admits composite container elements in structural solver queries, including their reconstruction and exact-query model validation. Python source annotations admit supported composite elements; nested aliases remain subject to the conservative ownership rules.

Worker protocol v15 additionally admits nested element evidence. Each condition is closed over its own element binder; nested evidence may select its container from that element but cannot capture an enclosing element in its condition. Contract lowering assigns distinct binders to nested levels. Model validation replays generated string observations recursively over every complete domain representative, including inside nested conditions. Neither a binder collision nor a free-variable capture can establish successful verification.

Every stored value, including padding and absent optional payloads, must have a matching recursive sort, canonical integer/key representation and canonical unused snapshot fields. Source-domain checks apply only to present payloads and valid container indices/keys. String contents must be complete valid code-point vectors throughout the stored representation. Query axioms and string observations guard optional payload domains by their tags. Explicit payload projections still contribute their own observations and require source definedness checks.

Validation of derived terms follows their generated string observations. A computed or projected snapshot does not gain an unasserted source-domain axiom; binding axioms and explicit validity predicates supply those facts.

Concrete string contents are checked together with every assertion of the exact query. Snapshot models still establish modeled inhabitation rather than concrete Python container input witnesses. HIR replay reconstructs supported straight-line concrete scalar violations and checks input contracts and the failed source obligation. Replay conservatively declines structured control flow, calls and abstract values; without execution correspondence, a failed abstract goal remains unproved. Replay does not import or execute target modules, and its shared primitive model is not an independent proof of arithmetic semantics.

Flow typing considers both branch arms and zero-trip loop paths, including literal guards. It can reject an unbound read, incompatible join or fallthrough before stronger SMT path reasoning would establish that the path is unreachable. Each source assignment uses the local contract active at that source position; a later annotation cannot constrain an earlier write retroactively.

Line/character presentation is outside the current diagnostic interface. Dependency upgrades require repeating field, literal and source-range probes.

Use a Rust Z3 binding only inside smt, with a pinned compatible pair of crate and solver versions. Emit SMT-LIB from the same logical IR. Z3 AST types and lifetimes must not spread throughout the type checker. See the z3 crate.

Record input hashes, model versions, qualifier sets, solver versions and settings, limits, and generated obligations. Cache keys also include callee contracts and verification status. A fixed random seed alone is not a promise of reproducibility across solver versions.

Results and diagnostics

Result Meaning Success
verified All final obligations hold; dependent functions and effects are checked Yes
counterexample A violation is confirmed for admissible inputs along a reachable execution No
unproved An abstract countermodel or insufficient invariant prevents proof No
unknown Solver uncertainty or time/resource limits prevent a decision No
unsupported A construct, type, or effect cannot be translated with the required semantics No
error Invalid syntax, base types, annotations, configuration, or an internal failure No

A Z3 sat result establishes a model of the query, not automatically a concrete Python counterexample. An unknown result establishes neither proof nor refutation. See Programming Z3.

Promoting a result to counterexample requires establishing that inputs meet all contracts and reach the violation through the actual path conditions. This can use an exact scalar path model or a restricted core evaluator. Do not automatically import and execute user modules to replay models. Otherwise retain unproved.

For a function returning x - 1 as Nat from a Nat input, report the source-level witness x = 0, result = -1, and failed goal result >= 0. For loops, show the inferred invariant and distinguish initiation, preservation, and exit failures, including the relevant edges.

Continuing analysis after unsupported code must not turn the overall report into verified. CLI exits are 0 when every requested target verifies, 1 for unmet verification, and 2 for execution/configuration failure, as specified in the report contract.

Unsatisfiable preconditions make logical implications vacuously valid. Check entry satisfiability separately, reject unsat as an uninhabited contract and do not claim input existence after unknown. Treat assert p as a proof obligation, never as an unchecked assumption that makes later obligations succeed.

An unsatisfiable declared entry contract is error: uninhabited-contract, even if its implications are vacuously valid. An inconclusive entry check is unknown: contract-inhabitation. Require a satisfiable entry contract for verified. With abstract container models, a solver witness establishes model inhabitation only; record that distinction and do not present it as a concrete admissible Python input unless reconstructed and checked. Finite generic specializations each undergo this check.

For entry assertions containing admitted recursive applications, an application-free conjunction relaxation may supply a candidate model. Evaluate every original assertion on that complete model using only independently admitted definitions, preserving lazy guards and complete snapshot arrays. Success requires every assertion to evaluate to true, with a shared budget of 4,096 evaluation nodes and depth below 128. String-valued bindings remain excluded from this optional candidate path; ordinary SMT queries reconstruct them. Missing definitions, scoped applications, false assertions and evaluation limits decline the candidate and fall back to the original SMT query. Candidate search is incomplete and never determines uninhabitation by failed sampling. Evidence records a modeled input witness checked by bounded evaluation; universal proof obligations still use the ordinary conservative worker path. No Python code or contract lambda executes during this check.

Reports and aggregation

Emit text and versioned JSON reports. Each target record contains its resolved identity, source hash and ranges, final status and reason code, obligation kinds, inferred/user invariants, dependency results, checked scope, model/concrete inhabitation evidence, limits, query counts, and timings. Retain secondary diagnostics when a target has multiple failures; an implementation failure takes precedence over a logical classification.

A caller whose required callee is not verified or explicitly modeled receives a non-success dependency diagnostic with the callee’s location and status. A trusted result is still conditional on listed models; retain those assumptions internally. Selecting one function certifies only that function and its checked dependency closure. A module/package-wide success requires every selected function, including all generic specializations, to succeed.

Exit 0 only when all requested targets verify with no skipped required obligations; exit 1 for logical violations, unproved/unknown/unsupported targets, invalid source contracts, or base-type errors; exit 2 for configuration, installation, or internal execution failures. An empty target selection is a configuration error. Refinement suppressions are unsupported. # type: ignore and opaque metadata cannot change an obligation’s status.

The compatibility inventory records the Rust toolchain, parser revision, Z3 binding and solver pair, model/report/cache/worker versions and Python syntax baseline.

Run solver work in a cancellable worker process so the driver can enforce a target deadline and recover from native failure. Cancellation or solver failure cannot leave a cached verified result. The local browser playground compiles the same verifier and pinned Z3 to WebAssembly. It retains model validation and monotonic target/query limits, and exposes neither native process isolation nor verified-closure cache reuse. Its single-module editor and report UI do not expand the supported Python subset.
