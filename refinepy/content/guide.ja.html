関数を検証する

  1. サンプルを選び、サンプルを読み込むを押します。
  2. playground.py を編集します。別のサンプルを読み込むと、ソースが置き換わり、取り消し履歴も消えます。
  3. 検証する関数に関数名を指定します。* は型注釈付き関数をすべて選択します。
  4. 検証を押すと、エディターの横に結果が表示されます。キャンセルで実行を停止できます。

ソースや関数の指定を編集すると、前の結果は消えます。検証中はエディターが読み取り専用になります。ページを再読み込みすると、最初のサンプルに戻ります。ヘッダーのガイドとリファレンスは同じタブで開きます。

ヘッダーの EN / JP で英語と日本語を切り替えられます。操作、サンプル名、エディターの検索操作、結果の要約、ガイド、リファレンスの本文をフロント側で翻訳します。切り替えても、ソース、取り消し履歴、関数の指定、実行中の検証、既存の結果を保持します。ブラウザーの保存機能が使える場合、言語設定を保存します。初期設定は英語です。Python サンプル、コード例、検証器の診断原文、証拠の記録、処理段階の識別子、JSON は変更しません。docs/ 内の詳細な技術文書は英語です。

ヘッダーの3ページは、エディターを再読み込みせずに切り替わります。.html URL の直接表示、見出しへのリンク、ブラウザーの戻る・進むに対応しています。ページ全体を再読み込みするとソースは初期化されます。ドキュメントを読み込めなかった場合は、その旨を表示します。

契約を書く

リポジトリの二分探索サンプルは、重複を含む任意の長さの整列済みリストについて、完全な探索契約と停止性を検証します。検証済みの区間に関する帰納補題が、区間を狭めても要素の所属関係を維持します。静的アサーションは補題を実行せずに利用します。仕様を参照してください。

Annotated で型に述語を付けます。lambda の最初の引数は制約される値です。戻り値の述語では関数の引数も指定でき、結果と入力の関係を記述できます。

from refinepy import Refine
from typing import Annotated

Nat = Annotated[int, Refine(lambda v: v >= 0)]

def increment(x: Nat) -> Annotated[int, Refine(lambda result, x: result == x + 1)]:
    return x + 1

この契約は、入力が非負で、結果が入力よりちょうど1大きいことを要求します。戻り値の式を x - 1 に変更して、もう一度検証してみてください。

数値サンプルを選ぶ

メニューには基本サンプルの 値を指定した範囲に収めると、フィボナッチ数：高速倍加法の検証、二分法による整数平方根、数列の和と閉形式、厳密な丸めと有理数によるスケール変換、符号付き整数の商と余りがあります。

数値サンプルガイドは、具体的な数値で式を説明し、証明の方法と制限を示します。例えば平方根の契約は r*r <= n < (r+1)*(r+1) です。丸めでは誤差の範囲と、ちょうど中間の値の扱いを指定します。サンプルを選び、サンプルを読み込むを押して、* で検証してください。コンテナーのサンプルは、リポジトリと回帰テストに残っています。

文字列の内容を検証する

文字列の内容比較、長さ、連結、安全な整数の添字アクセス、ステップ1のスライスを、本体と述語で使えます。読み取りでは添字が範囲内であることを証明します。負の添字は末尾から数えます。スライスは境界を切り詰め、境界の省略と None、ステップの省略と None、定数1に対応します。

from typing import Annotated
from refinepy import Refine, requires

@requires(lambda text: len(text) > 0)
def first(text: str) -> Annotated[str, Refine(lambda result: len(result) == 1)]:
    return text[0]

def append(left: str, right: str) -> Annotated[str, Refine(lambda result, left, right: len(result) == len(left) + len(right))]:
    return left + right

モデルはサロゲートを含むPythonの全コードポイントを保持します。大小比較はコードポイントの辞書式順序で、"a" < "aa" < "b" が成り立ちます。固定長タプルも、共通の要素が比較可能な整数・bool・文字列・入れ子のタプルなら辞書式に比較できます。対応する両要素がNoneの場合も扱えます。文字列メソッド、f-string、その他のスライスステップは未対応です。文字列の証拠は4,096コードポイントまで完全に再構築し、それを超える証拠は unknown になります。文字列モデルと対応表を参照してください。

タプルの結果全体を記述する

契約内のタプルリテラルで、結果の全フィールドをまとめて記述できます。

from refinepy import ensures

@ensures(lambda result, x: result == (x, x + 1))
def pair(x: int) -> tuple[int, int]:
    return x, x + 1

タプルの構築、連結、静的なスライスは、事前条件、細分化述語、アサーション、ループ不変条件で使えます。例えば result == pair_input[::-1] は固定長タプルの反転を表します。フィールドには省略可能値、入れ子のタプル、対応する要素型のリストやマッピングを含められます。後のスライスが空になったり、別のフィールドで等価比較が既に偽になったりする場合も、各フィールドの式は安全でなければなりません。タプルを構築する前に、条件付きの読み取りをガードしてください。リファレンスとタプルモデルを参照してください。

関数は、ペア全体の契約を持つ2つのリストを返せます。

from typing import Annotated
from refinepy import Refine

def split_at(xs: list[int], i: int) -> Annotated[
    tuple[list[int], list[int]],
    Refine(lambda result, xs, i: result == (xs[:i], xs[i:])),
]:
    return xs[:i], xs[i:]

期待されるフィールド型があるため、tuple[list[int], list[int]] の結果には return [], [] も使えます。リストの要素自体には引き続きスカラー型を使います。タプルから取り出したリストは借用されており、取り出すだけでは更新できません。ローカルで構築したリストは書き込み後に直接返してください。タプルへの格納で、書き込んだリストの別名参照を禁止する規則を回避することはできません。

整数入力を乗算する

本体と述語では、2つの変数を整数乗算のオペランドにできます。例えば、任意の整数入力の平方は非負です。

from refinepy import Refine
from typing import Annotated

def square(a: int) -> Annotated[int, Refine(lambda result: result >= 0)]:
    return a * a

square を選択して検証します。result >= 0 を result > 0 に変えると、a = 0 の反例が得られます。積には Annotated[int, Refine(lambda result, a, b: result == a * b)] の依存する戻り値契約を使えます。整数の a *= b でも右辺に変数を使え、再束縛後に宣言済みのローカル契約を検査します。

非線形整数の証明義務は、ソルバーの能力や設定された制限を超え、unknown になる場合があります。構文への対応は、すべての多項式の性質を証明できるという保証ではありません。リファレンスと整数モデルを参照してください。

整数入力で除算する

事前条件や分岐で、除数が0でないことを示します。正負どちらの除数にも対応し、Python の床方向への丸めと余りの符号に従います。

from refinepy import requires, ensures

@requires(lambda d: d != 0)
@ensures(lambda r, a, d: a == r[0] * d + r[1] and
    (0 <= r[1] < d if d > 0 else d < r[1] <= 0))
def divide(a: int, d: int) -> tuple[int, int]:
    return a // d, a % d

ガードのない変数の除数が0になり得る場合、定義可能性の証明義務に失敗します。a // d if d else 0 は対応する安全な書き方です。//= と %= も同じ検査を行います。述語にも d != 0 and a % d == 0 などのガードが必要です。変数の除数を使う証明は unknown になる場合があります。整数モデルを参照してください。

ローカルリストを構築して更新する

管理対象の examples/local-lists/lists.py には、範囲の構築、フィルター、置換、交換の完全なサンプルがあります。プレイグラウンドに貼り付けて検証できます。数値メニューには 符号付き整数の商と余りがあります。

examples/partition/partition.py は、負数と非負数への厳密な分割を証明し、入力を変えずに両方の結果を安全に更新します。ソースをエディターに貼り付け、* で検証してください。

1つのローカル名に新しいリストを構築します。入力リストの値を関数入口のまま保ちつつ、新しいリストの内容を更新できます。

from refinepy import requires, ensures

@requires(lambda xs, i: -len(xs) <= i < len(xs))
@ensures(lambda r, xs, i, value:
    len(r) == len(xs) and r[i] == value
    and r == xs[:i if i >= 0 else len(xs) + i] + [value]
        + xs[(i if i >= 0 else len(xs) + i) + 1:])
def replace(xs: list[int], i: int, value: int) -> list[int]:
    out = xs[:]
    out[i] = value
    return out

単独の append と extend、リストの += で結果を構築できます。空リストには out: list[int] = [] などの明示的なローカル型が必要です。追加・置換する要素は、非負や偶数といった細分化を含む要素契約を満たす必要があります。リスト全体のローカル細分化は書き込みのたびに検査します。ループでは明示的な不変条件や減少尺度が必要になる場合があります。要素の細分化は、関数が読んだ要素だけでなく、有効な要素すべてを記述します。細分化の lambda は、それぞれ独自の要素値を束縛します。

置換の契約は、負の添字を含め、前後の要素列全体を保持します。ローカルリストのサンプルは、build_range が正確に 0 から n - 1 を返すこと、evens が入力中の偶数をすべて元の順序で、重複も保持して返すことも証明します。定義を論理に取り込んだ仕様と、正確な接頭部分の不変条件により、構築中に仕様関数を実行せずに契約を表します。片側の要素の細分化がより強くても、再帰的に比較可能な要素のソートが一致すればリストの等価比較ができます。完全な契約を参照してください。

コンテナーの要素には、タプル、省略可能値、その他の対応するコンテナーを使えます。

def coordinates() -> list[tuple[int, int]]:
    out: list[tuple[int, int]] = [(1, 2)]
    out.append((3, 4))
    assert out == [(1, 2), (3, 4)]
    return out

def missing_values() -> list[int | None]:
    out: list[int | None] = [None, 2]
    out[0] = 1
    assert out[0] is not None
    return out

入れ子の空リテラルは、戻り値型、ローカル注釈、隣接する型付きリストから型を受け取ります。入れ子のフィールドと要素の細分化も証明義務です。新しく確保した外側のリストは、借用した内側のリストの所有権を与えません。rows[0] を読むだけでは、そのリストを変更できません。内包表記でも、対応する複合要素を構築できます。

def adjacent_pairs(xs: list[int]) -> list[tuple[int, int]]:
    return [(x, x + 1) for x in xs]

各内包表記には同期のジェネレーターを1つ使います。入れ子の内包表記は変数スコープが別です。フィルターと、1つの内包表記内の複数ジェネレーターには対応していません。要素の構築は、すべての入力要素について契約を満たし、安全である必要があります。空の入力では要素の式を評価しません。定義を取り込むヘルパーの呼び出しにも、依存先の検証成功が必要です。

検証済みのソースヘルパーを使い、新しいリストの構築を共通化できます。

from refinepy import ensures

@ensures(lambda result, xs: result == xs)
def copy(xs: list[int]) -> list[int]:
    return xs[:]

@ensures(lambda result, xs, value: result == xs + [value])
def append_copy(xs: list[int], value: int) -> list[int]:
    out = copy(xs)
    out.append(value)
    return out

検証器はヘルパーの実際の確保処理と、すべてのソース依存先を検査します。同じ等価契約でも return xs では呼び出し側の書き込みを許可しません。両方の分岐が新しいリストを返す必要があり、借用した結果を返す分岐があると所有権を移せません。インポートしたヘルパーや認証済み呼び出しの連鎖にも対応します。推論された呼び出し結果は、更新時も要素の細分化を保持します。

ヘルパーが独立した2つのリストを返し、直接のアンパックで両方を移譲することもできます。

@ensures(lambda result, xs: result == (xs, xs))
def copies(xs: list[int]) -> tuple[list[int], list[int]]:
    return xs[:], xs[:]

@ensures(lambda result, xs: result == (xs + [1], xs + [2]))
def grow(xs: list[int]) -> tuple[list[int], list[int]]:
    left, right = copies(xs)
    left.append(1)
    right.append(2)
    return left, right

証明書は、入れ子のコンテナー内部に保持する参照も含め、確保が独立していることを検査します。同じリストを2回返したり、入力を返したりする場合は認められません。呼び出し時に直接アンパックしてください。タプルをローカルに保存してからフィールドを取り出すと別名参照が残り、書き込みは許可されません。所有権規則は、転送、条件付き、定義を取り込む呼び出し、ジェネリックな結果について説明します。examples/partition/partition.py は、順序と重複を含む厳密な負数・非負数の分割を証明し、返された両方のリストを更新します。接頭部分の仕様は全域で定義され、ループには検査済みの減少尺度があります。

alias = out として保存すると、書き込みは未対応になります。入力リストや借用した呼び出し結果は、代入だけでは書き込み可能になりません。out を更新するループは、変化しない入力か out[:] などの新しいコピーを走査する必要があります。構築後の通常の走査には対応します。pop、clear、スライス代入、入れ子の変更呼び出しは未対応です。所有権と書き込みの規則を参照してください。

固定長タプルと許可する値

Literal で許可するスカラー値の有限集合を指定します。固定長タプルは各フィールドの契約を保持し、等価比較、連結、静的なスライスに対応します。

from refinepy import Refine
from typing import Literal

Mode = Literal["read", "write"]

def reverse_pair(pair: tuple[Literal[0, 1], Mode]) -> tuple[Mode, Literal[0, 1]]:
    return pair[::-1]

Literal の引数は同じ基底型を持つ必要があります。タプルのスライス境界とステップは、静的に分かる整数、または省略・None で指定します。ステップは0以外です。正確な制限はリファレンスを参照してください。

関数の事前条件を追加する

入力間の関係には、インポートした requires デコレーターを使います。後で宣言したものも含め、どの入力も参照でき、複数行に記述できます。

from refinepy import requires

@requires(
    lambda xs, i: 0 <= i < len(xs)
)
def read_at(xs: list[int], i: int) -> int:
    return xs[i]

import refinepy as rp や from refinepy import requires as pre も使えます。デコレーターは Python 実行中に述語を実行したり契約を検査したりせず、元の関数を保持します。装飾したコードを実行するには refinepy の補助パッケージをインストールしてください。検証器は、ソースをインポートせずに読みます。requires、reflect、decreases にはデコレーターを使い、旧コメント形式は拒否されます。ループ不変条件には通常の invariant(lambda ...) 呼び出しを使います。コメント形式は非推奨です。束縛規則はリファレンスを参照してください。

比較の連鎖は 0 <= i < len(xs) のように書けます。None、in、not in を含む連鎖は、left is None and right is None のように個別の真偽式に分けてください。関数の既定値は、スカラー・None リテラル、または int / bool / str リテラルの平坦なタプルに限ります。入れ子のタプルや None を含むタプルの既定値は未対応です。対応する形式と制限を参照してください。

ensures で戻り値の契約を書く

ensures を使うと、Annotated の内部ではなく関数の上に戻り値の細分化を書けます。関数シグネチャには戻り値の基底型を残します。

from refinepy import ensures

@ensures(lambda result, n: result == n + 1)
def increment(n: int) -> int:
    return n + 1

@ensures(lambda n: n + 0 == n)
def identity_lemma(n: int) -> None:
    return None

値を返す場合、lambda の最初の引数が結果を表し、以降の引数は関数入口の入力を指定します。None を返す場合は、すべての lambda 引数が入口の入力を表すため、証明関数にダミーの結果引数は不要です。複数の ensures と既存の戻り値の Refine メタデータは、すべて成立する必要があります。述語は静的に検査され、Python 実行中には動きません。規則の詳細はリファレンスを参照してください。

再帰の停止性を検査する

decreases で整数の尺度を追加します。各再帰呼び出しの尺度は非負で、関数入口の尺度より厳密に小さくなければなりません。

import refinepy
from refinepy import Refine
from typing import Annotated

Nat = Annotated[int, Refine(lambda v: v >= 0)]

@refinepy.decreases(lambda n: n)
def count(n: Nat) -> Annotated[int, Refine(lambda r, n: r == n)]:
    return 0 if n == 0 else 1 + count(n - 1)

count を選んで検証します。count(n - 1) を count(n) に変えると、停止性の証明義務に失敗します。リストのスライスに対する再帰では len(xs) も使えます。尺度は、ローカルで再代入しても元の入力を参照します。

成分が複数ある場合は、空でない整数タプルリテラルを返します。最初に異なる成分が減少する必要があり、それより後の成分は再設定できます。

@refinepy.decreases(lambda n, m: (n, m))
def lex_count(n: Nat, m: Nat) -> int:
    if m > 0:
        return lex_count(n, m - 1)
    if n > 0:
        return lex_count(n - 1, 3)
    return 0

再帰呼び出し時に、すべての成分が非負である必要があります。ソース内の全呼び出し先は独立に停止することを示し、ループには次節のように明示的な尺度が必要です。このデコレーターのない関数も、再帰の停止性を証明せずに正常な戻り値の契約を検証できます。成功すると termination: の証拠が追加されます。Python の再帰深度や資源の制限は保証に含まれません。リファレンスを参照してください。

ループの停止性を検査する

通常の invariant と decreases 呼び出しをループの直前に置きます。lambda の束縛名は、現在のループ入口のローカル変数を指定します。連続する不変条件は論理積になり、1つの尺度をどちらの順序でも添えられます。通常の Python 型検査器でも使えます。補助パッケージは lambda を呼び出しません。

from typing import Annotated
from refinepy import Refine, invariant, decreases

Nat = Annotated[int, Refine(lambda v: v >= 0)]

def count_to(n: Nat) -> Annotated[int, Refine(lambda r, n: r == n)]:
    i = 0
    invariant(lambda i, n: 0 <= i <= n)
    decreases(lambda i, n: n - i)
    while i < n:
        i += 1
        if i % 2 == 0:
            continue
    return i

count_to を選んで検証します。不変条件は、反復に関する帰納法でループ入口の性質を示します。尺度は、実行する各反復で非負となり、通常の経路と continue の両方の後戻り辺で厳密に減少することで停止性を証明します。尺度を i に変えたり、i を増やさずに continue する経路を追加したりすると失敗します。尺度のない不変条件は部分正当性のみを証明し、ループの停止性の証拠は公開しません。

ループの尺度は (n, m) のようなタプルにも対応します。入れ子のループには、それぞれ尺度が必要です。対応する for でも同じ呼び出しを使います。ローカル変数はループ前に束縛済みである必要があり、未束縛の反復変数は lambda の束縛名にできません。尺度は、本体の前かつ for の対象を束縛する前に記録します。break、return、反復0回では減少を要求しません。最後の反復を含むすべての後戻り辺で、次の尺度が定義され非負である必要があります。max(n - i, 0) でカウントダウンを全域で定義できます。

独立した停止性検査は、すべての呼び出し結果の要約を取り除き、不変条件の初期成立と保持を再検査します。そのため、呼び出し先の結果契約に依存する証明は未完了のままになる場合があります。全呼び出し先は独立に停止する必要があります。Python は各ループに到達する前にマーカー呼び出しを1回実行しますが、述語や尺度の本体は実行しません。リファレンスと仕様を参照してください。

関数についての等式を証明する

全域で定義されたスカラー式の関数に @refinepy.reflect を付けると、実際の定義を契約で使えます。補題は、等式を戻り値の細分化として記述し、None を返せます。

from __future__ import annotations
import refinepy
from refinepy import Refine
from typing import Annotated

@refinepy.reflect
def inc(x: int) -> int:
    return x + 1

def lemma(x: int) -> Annotated[None, Refine(lambda _, x: inc(inc(x)) == x + 2)]:
    return None

lemma を選んで検証します。x + 2 を x + 3 に変えると証明に失敗します。別の検証対象の関数が補題を呼び出し、正常な戻り値の契約を使えます。定義を取り込む関数は、代入、平坦なアンパック、アサーション、分岐、return に対応します。型注釈には、積、省略可能値、対応するコンテナーを含む、細分化のない対応する値型を使います。入れ子の細分化と事前条件は対象外です。直接再帰には、後述する追加要件があります。減少を検査する再帰補題は、後述のように帰納法で命題を証明できます。制限はリファレンスを参照してください。

例えば、ガード付きのマッピング参照を論理関数にできます。

@refinepy.reflect
def find_value(values: dict[str, int], key: str) -> int | None:
    if key not in values:
        return None
    result = values[key]
    return result

def check_lookup(values: dict[str, int], key: str) -> None:
    assert (find_value(values, key) is None) == (key not in values)

検証器は check_lookup で定義を使う前に、find_value の参照ガードを検査します。定義を取り込む本体では、ループとコンテナーへの書き込みは未対応です。呼び出し側が find_value(values, key) == find_value(values, key) を使う場合でも、ガードを除くと検証に失敗します。省略可能値の内容へのアクセスや変数の除数にも、同じ独立した安全性検査が必要です。

補題を実行せずに使う

関数内のローカル注釈は Python では評価されません。静的な Assert 注釈により、実行時の呼び出しを追加せず、検証済みの補題を使えます。

from typing import Annotated
from refinepy import Assert

def use_lemma(x: int) -> int:
    x: Annotated[int, Assert(
        lambda value: inc(inc(value)) == value + 2,
        using=lambda arg: lemma(arg),
    )]
    return x

上の inc と lemma のサンプルに、この関数を追加してください。検証器は補題の安全性と停止性、実際の引数を検査してから、事後条件を使ってアサーションを証明します。事後条件とアサーションが完全に一致する必要はありません。正常に戻る場合の契約が検証できても、停止しない補題は静的な証明に使えません。

using のない Assert(lambda value: ...) は、現在の事実から命題を検査します。どちらの形式も、束縛済みのローカル変数に適用し、既存の宣言契約がない限り、その後の代入は制約しません。lambda の最初の束縛名は現在の値を受け取ります。lambda value, y: value < y などの追加の束縛名は、現在束縛されているローカル変数を明示的に指定します。using の lambda は独自のローカル依存を列挙し、複数の引数を補題に渡せます。自由変数としてローカル変数を取り込むことには対応しません。入力を再束縛した場合もアサーション時点の値を使い、その後の変更で確立済みの事実は更新されません。入力、結果、ローカル宣言の契約には Refine を使います。リファレンスと二分探索の証明を参照してください。

再帰スカラー関数の定義を取り込む

reflect と decreases を組み合わせ、停止する再帰定義を範囲を限定した等式で使います。

from __future__ import annotations
import refinepy
from refinepy import Refine
from typing import Annotated

@refinepy.reflect
@refinepy.decreases(lambda n: max(n, 0))
def count(n: int) -> int:
    return 0 if n <= 0 else 1 + count(n - 1)

def bounded(n: Annotated[int, Refine(lambda v: 0 <= v <= 7)]) -> Annotated[
    None, Refine(lambda _, n: count(n) == n)
]:
    return None

bounded を選んで検証します。ソースの定義は、等式を使う前に独立した停止性検査に通る必要があります。再帰引数を n に変えると、それ以外が自明な等式でもこの検査に失敗します。

スカラーのみの再帰定義では、入力と結果は細分化のない int または bool、戻り値は1つの式、事前条件なしで記述します。呼び出しは定義を8層まで展開します。それより先は未解釈のままとなり、結論が出ない問い合わせは、偽の等式の一部も含め unknown になります。範囲を限定した等式に使えますが、範囲を限定しない等式には明示的な帰納補題が必要です。再帰リストは、次節のように展開上限が小さくなります。リファレンスを参照してください。

再帰定義には、積と省略可能値も使えます。

@refinepy.reflect
@refinepy.decreases(lambda n: max(n, 0))
def carry(n: int, pair: tuple[list[int], int | None]) -> tuple[list[int], int | None]:
    if n <= 0:
        return pair
    return carry(n - 1, pair)

def check_carry(xs: list[int]) -> None:
    assert carry(1, (xs, None)) == (xs, None)

マッピングとシーケンスの入力・結果にも対応します。検証器は、再帰等式を通して省略可能値の存在状態と、有効なコンテナーの内容を保持します。コンテナーを含むシグネチャでは、既定で定義を3層まで展開します。範囲を限定しない主張には、帰納補題が必要になるか、証明未完了になる場合があります。

再帰リスト関数の定義を取り込む

再帰関数は、細分化のない list[int]、list[bool]、list[str] を受け取ったり返したりできます。減少尺度に len(xs) を使い、条件付きの添字アクセスをガードします。

from __future__ import annotations
import refinepy
from refinepy import Refine
from typing import Annotated

@refinepy.reflect
@refinepy.decreases(lambda xs: len(xs))
def reverse(xs: list[int]) -> list[int]:
    return [] if len(xs) == 0 else reverse(xs[1:]) + [xs[0]]

def bounded(xs: Annotated[list[int], Refine(lambda v: len(v) <= 2)]) -> Annotated[
    None, Refine(lambda _, xs: reverse(xs) == xs[::-1])
]:
    return None

bounded を選んで検証します。呼び出し側が定義を使う前に、ソース本体が安全性と停止性の検査に通る必要があります。空リストのガードを除くと読み取りの証明義務に失敗し、xs[1:] を xs に変えると減少の検査に失敗します。

リストを含むシグネチャは定義を3層展開し、残りの呼び出しは未解釈のままです。置換中にスライス式は急速に大きくなり、既存の 128 KiB 制限が適用されます。上の長さの制限は、空リストの基底ケースに達するための層数を確保します。制限がないと、この等式では結論が出ません。任意の長さについて証明するには、次の明示的な帰納補題を使います。未解釈の呼び出しが残る充足可能な問い合わせは、偽の等式も含め unknown になり、ソースの反例は生成しません。リファレンスを参照してください。

リストの等式を証明する

通常の Python リストの連結とスライスで、全域で定義されたヘルパーを記述します。

from __future__ import annotations
import refinepy
from refinepy import Refine
from typing import Annotated

@refinepy.reflect
def append(xs: list[int], ys: list[int]) -> list[int]:
    return xs + ys

@refinepy.reflect
def reverse(xs: list[int]) -> list[int]:
    return xs[::-1]

def reverse_append(xs: list[int], ys: list[int]) -> Annotated[
    None, Refine(lambda _, xs, ys:
        reverse(append(xs, ys)) == append(reverse(ys), reverse(xs)))
]:
    return None

reverse_append を選んで検証します。この等式は任意の有限長のリストを扱います。リストの等価比較は長さとすべての有効な要素を比べ、リストの範囲外の内部値は無視します。append(xs, []) == xs や連結の結合則も記述できます。両オペランドの要素型と要素契約は、再帰的に比較可能で一致する必要があります。このサンプルは非再帰の定義を使い、任意の有限リストについて等式を証明します。再帰リストの定義は前述のように有限の展開に対応し、次のサンプルでは明示的な帰納補題を追加します。

帰納法でリストの等式を証明する

戻り値の命題と decreases を持つ、通常の再帰補題を使います。より小さい各自己呼び出しが帰納仮説を与えます。このサンプルは、任意の有限長について反転とスライスが等しいことを証明し、その結果から反転と連結の等式を証明します。

from __future__ import annotations
import refinepy
from refinepy import Refine
from typing import Annotated

@refinepy.reflect
@refinepy.decreases(lambda xs: len(xs))
def reverse(xs: list[int]) -> list[int]:
    return [] if not xs else reverse(xs[1:]) + [xs[0]]

@refinepy.decreases(lambda xs: len(xs))
def reverse_spec(xs: list[int]) -> Annotated[
    None, Refine(lambda _, xs: reverse(xs) == xs[::-1])
]:
    if xs:
        reverse_spec(xs[1:])
        return None
    return None

def reverse_append(xs: list[int], ys: list[int]) -> Annotated[
    None, Refine(lambda _, xs, ys: reverse(xs + ys) == reverse(ys) + reverse(xs))
]:
    reverse_spec(xs + ys)
    reverse_spec(xs)
    reverse_spec(ys)
    return None

reverse_append を選んで検証します。長さの上限はありません。ドライバーは reverse を独立に検査してから、補題の基底ケース、戻り値の命題、厳密な減少を検査します。自己呼び出しを除くと帰納段階に仮説がなくなり、reverse_spec(xs) に変えると減少に失敗します。誤った基底ケースも失敗します。成功した証明には induction:... と termination:... の証拠が残ります。

これは、受け入れ済みの定義の1段階の基礎等式と、通常の再帰呼び出しの契約を使います。証明を局所的に保つため各分岐で return してください。分岐を合流させると候補述語の推論が必要になり、結論が出ない場合があります。直接再帰と整数または辞書式の尺度が必要で、ループには独自の尺度を付けます。相互帰納と自動証明探索は未対応です。decreases がない補題は部分正当性を保持しますが、帰納の証拠は付きません。リファレンスを参照してください。

結果を読む

結果の冒頭には、選択した関数の 検証済み、要確認、失敗 の件数が表示されます。要確認は unproved、unknown、unsupported、失敗は counterexample、error をまとめたものです。個別の意味は各カードに残ります。エラーは必ずしもソースのバグを意味しません。レポート全体の診断は別に表示され、診断がある場合は「すべて検証済み」にはなりません。各カードには短い結論と、別の停止性の要約があります。検証の詳細を展開すると、ソルバーのコスト、検証した範囲、推論した不変条件、ソースの依存先、所有権の記録を含む証明の証拠を確認できます。JSON レポート全文には完全なレポートが残ります。

各関数には状態、停止性の要約、診断が表示されます。その関数自身の停止性の証拠を持つ検証済みの結果には、停止性：この関数と検証対象の呼び出しについて証明済みです。 と表示します。証拠がなければ、正常に戻る場合の契約は検証済みですが、停止性は証明されていません。失敗した結果や不確実な結果で、停止性が証明済みになることはありません。Python の再帰深度の安全性と資源の利用可能性はモデルの範囲外です。

状態 意味
verified 必要な証明義務を満たしました。
counterexample 妥当性を確認した反例がソースの契約に違反しています。
unproved 未証明の義務が残っています。これだけでソースのバグとは確定できません。
unsupported ソースが対応範囲外の形式を使っています。
unknown 制限やソルバーの不確実性により結果が得られませんでした。
error ソース、契約、設定、実行のいずれかが失敗しました。診断を確認してください。

unknown は、ソルバーの完全なモデルを、対応する表現や資源の制限内で再構築できなかったことを意味する場合もあります。コンテナーの要素を一部読むだけでは、有効なモデルとは確認できません。モデル検証規則を参照してください。省略可能値の内容に関する事実は、値が存在する場合に適用します。未使用の内容も、保存表現が整っているか検査します。入れ子の要素の証拠は、条件内で行う文字列の観測も含め、各コンテナー階層で検査します。この内部対応は、取り出した入れ子リストの所有権を確立しません。

依存する契約、事前条件、コンテナーの読み取り、ループ不変条件、対応・未対応の Python 構文の概要はリファレンスを参照してください。

フィボナッチ数の倍加法を検証する

examples/fibonacci/README.md のサンプルは、通常のフィボナッチ漸化式に対する高速倍加法を証明します。ensures は addition、pair、fast_fib の戻り値の細分化を表し、None の補題では結果の束縛名を省略します。再帰する addition 補題が2つの加法公式を帰納法で証明します。pair は静的アサーションで addition(k, k) に特殊化し、より小さい再帰呼び出しの契約から (F(n), F(n + 1)) を証明します。4つの対象すべてが添字の上限なしで検証できます。別の実行検査は、514個の添字を反復加算による正解値と比較します。

分岐する漸化式では、再帰定義の受け入れ前検査に 4 MiB の予算を使います。保存する1段階の定義、非循環の展開、問い合わせの等式には、より小さい上限が引き続き適用されます。この予算変更は証明の仮定を追加しません。リファレンスを参照してください。このサンプルは静的アサーションで加法の証明呼び出しの実行を避け、正しさのみを評価します。時間計算量については主張しません。Python の再帰深度と資源の制限は、停止性の保証に含まれません。
