リファレンス

refinepy は、型注釈付きの Python 3.12 関数の契約を検査します。以下の例は対応する記述方法を示し、ここで導入するインポートと型の別名を共有します。表は主な制限をまとめています。エディターの操作と結果の状態についてはガイドを参照してください。

数値プレイグラウンドには、基本の範囲契約と、フィボナッチ数、整数平方根、数列の和、厳密な有理数の丸め、符号付き除算の例があります。数値による説明、仮定、失敗する編集はサンプルガイドを参照してください。ソースは管理対象の Python ファイルからそのままコピーします。各結果には、それぞれの停止性の証拠が残ります。

コンテナーを扱う例はリポジトリと回帰テストに残っています。二分探索の証明は、任意の整列済みリストについて完全な探索の正しさと停止性を検査します。短い契約の演習は確保処理とウィンドウの読み取りを扱います。一般的な再帰仕様の問い合わせでは、結論が出ない場合があります。

ヘッダーの EN / JP で英語と日本語を切り替えられます。操作、サンプル名、エディターの検索操作、結果の要約、ガイド、リファレンスの本文をフロント側で翻訳します。切り替えても、ソース、取り消し履歴、関数の指定、実行中の検証、既存の結果を保持します。ブラウザーの保存機能が使える場合、言語設定を保存します。初期設定は英語です。Python サンプル、コード例、検証器の診断原文、証拠の記録、処理段階の識別子、JSON は変更しません。docs/ 内の詳細な技術文書は英語です。

ヘッダーの3ページは、エディターを再読み込みせずに切り替わります。.html URL の直接表示、見出しへのリンク、ブラウザーの戻る・進むに対応しています。ページ全体を再読み込みするとソースは初期化されます。ドキュメントを読み込めなかった場合は、その旨を表示します。

値の契約

Annotated で型に Refine(lambda ...) メタデータを付けます。lambda の最初の引数は制約される値です。複数の Refine 述語は and で結合します。

from refinepy import Refine
from typing import Annotated

Nat = Annotated[int, Refine(lambda v: v >= 0)]

def increment(x: Nat) -> Annotated[int, Refine(lambda result, x: result == x + 1)]:
    return x + 1

x: Nat は非負の入力を要求します。戻り値の契約は、入力よりちょうど1大きい結果を要求します。lambda の追加引数は関数の入力を指定します。引数の契約はそれより前の引数を参照でき、戻り値の契約はすべての引数を参照できます。本体で同じ名前に再代入しても、関数入口の値を表します。

from collections.abc import Sequence

def at(
    xs: Sequence[int],
    i: Annotated[int, Refine(lambda v, xs: 0 <= v < len(xs))],
) -> int:
    return xs[i]

型の別名とローカル変数の契約は単項述語を使います。count: Nat = 0 のようなローカル宣言は、その後の count へのすべての代入が Nat を満たすことを要求します。引数の契約は入口の値のみを制約します。関数のすべての引数と戻り値には型注釈が必要です。ローカル型は推論できます。

Literal の契約と固定長タプル

Literal は、基底型と許可する値を制限する契約になります。同じ基底型を持つ、空でない int、bool、str、None のリテラル集合を使います。符号付き整数、静的な別名、引用した注釈にも対応します。通常の制限のもとで、Literal を Annotated、省略可能値の内容、タプルのフィールド、スカラー型のコンテナー要素と組み合わせられます。

from refinepy import Refine
from typing import Literal

Mode = Literal["read", "write"]

def switch(mode: Mode) -> Mode:
    return "write" if mode == "read" else "read"

def reverse_pair(pair: tuple[Literal[0, 1], Mode]) -> tuple[Mode, Literal[0, 1]]:
    return pair[::-1]

基底型の混在（int/bool を含む）、計算した引数や名前で指定する引数、enum、入れ子の Literal は未対応です。整数 Literal は既存の数値表現を使うため、True は Literal[1] を満たします。Literal[True] は bool を要求し、整数の1を除外します。契約は代入、return、呼び出し引数で検査します。既定値は定義時に基底型を検査し、呼び出しがその値を使う際に細分化を検査します。

固定長タプルは、本体と述語で == / != に対応します。等価比較はフィールドごとに行い、bool/int の数値比較も使います。省略可能フィールドはタグと存在する内容、入れ子のタプルは再帰的に比較します。リストのフィールドは、再帰的に比較可能な要素のソートが一致する場合、有効な範囲の内容を比較します。マッピングや抽象シーケンスのフィールドの等価比較、リストの要素ソートの不一致は未対応です。長さの異なるタプルや、無関係なスカラーフィールド型は等しくありません。空の積を含め、両オペランドを1回ずつ評価します。

タプルリテラルと a + b は、本体と述語で固定長の積を構築します。スライスは選択したフィールド型を保持し、静的な整数または省略・None の境界、0以外の静的ステップに対応します。反転と境界の切り詰めも使えます。結果が空でも元の値を評価し、その証明義務を検査します。タプルの大小比較は共通の要素を辞書式に比較し、等しい接頭部分の後は長さで決めます。共通の要素は、比較可能な整数・bool・文字列・入れ子の固定長タプル、または対応する両要素がNoneである必要があります。先の要素で結果が決まり得る場合でも、省略可能値・コンテナー・互換性のない共通要素は受け入れません。比較の前に両タプルの全要素を評価します。動的な積のスライス境界は未対応です。

タプルのフィールドには、None、省略可能値、別の固定長タプル、対応するコンテナーを再帰的に含められます。文脈のフィールド型から空コンテナーリテラルの型を解決します。フィールドと要素の細分化は検査され、書き込み可能な list/dict 型はタプル内でも不変です。積の構築、連結、スライスは別名参照の可能性を保持します。書き込んだローカルリストをタプルに保存することは拒否され、リストのフィールドを取り出しても新たな所有権は証明されません。後述のように、検査済みの分離証明書を持つソースの結果を直接アンパックすれば、書き込み可能なリストを移譲できます。

リストとマッピングは、積、省略可能値、入れ子の対応するコンテナーを含められます。読み取りは入れ子の契約を保持します。入れ子のリストを取り出しても新たな所有権は証明されず、新しく確保した外側のリストにも借用した要素が残る場合があります。

関数の事前条件

@requires(lambda ...) で、後で宣言した引数も含む、関数入力間の関係を指定します。複数の事前条件は結合します。

from refinepy import requires

@requires(lambda xs, i: 0 <= i < len(xs))
def read_at(xs: Sequence[int], i: int) -> int:
    return xs[i]

補助パッケージは ensures、decreases、reflect も公開します。import refinepy as rp と from refinepy import requires as pre は、@rp.requires(...) と @pre(...) で使えます。再エクスポートも解決します。同名のユーザー関数は未対応です。requires、ensures、decreases は、通常の必須の位置引数を持つ lambda リテラルを、位置引数でちょうど1つ受け取ります。括弧で複数行の条件を書けます。@reflect に括弧は付けません。reflect または decreases の重複はエラーです。デコレーターの順序で契約は変わりません。

これらのデコレーターは元の関数と型を保持し、実行時に述語を実行したり契約を検査したりしません。Python コードの実行には refinepy の補助パッケージが必要ですが、検証器は対象コードをインポートしません。デコレーターは関数定義前にインポートする必要があり、TYPE_CHECKING の内部には置けません。その他のデコレーターは未対応です。ループの invariant コメントは非推奨です。後述する通常のマーカー呼び出しを使ってください。古い関数コメント形式はエラーです。

呼び出しは、呼び出し先の引数契約と事前条件を満たす必要があります。ソース内の呼び出し先も検査し、その事後条件が呼び出し側で使えるようになります。本体で呼び出せるソース関数が、自動的に述語でも呼び出せるわけではありません。

関数の事後条件

@ensures(lambda result, n: result == n + 1) は、-> int の注釈付き関数に戻り値の細分化を追加します。lambda の最初の引数は結果を表し、追加引数はソースでの再代入にかかわらず、不変の関数入口の入力を指定します。None の結果では、-> None の関数に @ensures(lambda n: proposition) と書き、結果の束縛名を省略します。引数のない lambda: proposition は、None の結果に限って使えます。戻り値の基底型注釈は必要です。別名も同じ束縛規則に従います。

from refinepy import ensures

@ensures(lambda result, n: result == n + 1)
def increment(n: int) -> int:
    return n + 1

@ensures(lambda n: n + 0 == n)
def identity_lemma(n: int) -> None:
    return None

複数の ensures と既存の戻り値の Refine メタデータは論理積になります。注釈付き細分化と同じ論理の部分集合、独立した定義可能性検査、return 検査、呼び出し側の契約を使います。事後条件で、自身や別の事後条件の定義可能性を正当化することはできません。lambda リテラルには通常の必須引数が必要で、インポート、別名、再エクスポートは事前条件の規則に従います。デコレーターの順序は契約を変えません。補助パッケージは述語を呼び出さず、呼び出し可能な関数の識別、型、注釈、実行時の動作も変更しません。定義を取り込む関数では、引き続き細分化のない戻り値契約が必要で、ensures は除外します。減少する再帰の None 補題では、ensures が注釈付き戻り値の細分化と同じ命題を与えます。帰納補題を参照してください。

停止性の尺度

トップレベル関数に @decreases(lambda n: expression) を1つ付けられます。lambda の束縛名は入口の引数を指定します。結果は int、または細分化のない整数成分からなる空でない固定長タプルリテラルで、述語言語の純粋性の制限に従います。尺度は入口の契約と事前条件のもとで定義される必要があります。各直接自己呼び出しでは、通常どおり引数を束縛し、尺度の定義可能性と厳密な辞書式の減少を証明します。現在と次のすべての成分が非負である必要があります。スカラーなら 0 <= next < entry です。最初に異なるタプル成分が減少し、それより後の成分は再設定できます。空・入れ子のタプル、bool 成分、動的なタプル構築はエラーです。基底ケースの尺度は非負でなくても構いません。max(n, 0) と len(xs) が使えます。ローカルの再代入は関数入口の尺度を変えません。

ループでは、直前の通常の decreases(lambda ...) 呼び出しを使い、必要に応じて invariant(lambda ...) を添えます。実行する各反復は、for の対象を束縛する前に、束縛済みのループ入口のローカル変数について、定義された非負の尺度を記録します。通常の後戻り辺と continue の後戻り辺はすべて、その記録に対して定義可能性、非負性、厳密なスカラーまたは辞書式の減少を示す必要があります。break、return、反復0回には減少を要求しません。最後の後戻り辺にも、定義された非負の次の尺度が必要です。max(n - i, 0) で負への落ち込みを防げます。入れ子のループはそれぞれ尺度が必要です。未束縛の反復変数や内部のイテレーターカウンターは lambda の束縛名にできません。

全呼び出し先は独立に停止する必要があります。信頼されたモデルと相互再帰は未対応です。停止性の証明を要求する場合、到達不能なものを含め、すべてのループに尺度が必要です。独立した減少証明では、すべての呼び出し結果の契約を無視し、固定した不変条件の定義可能性、初期成立、保持を再検査します。そのため、結果に依存する減少や不変条件は証明未完了になる場合があります。証拠の公開前に、すべてのジェネリック特殊化が通る必要があります。

ループのない非再帰関数や、全ループに明示的な尺度を持つ非再帰関数も、検査対象の呼び出しの閉包全体が停止すると停止性の証拠を得ます。レポートには termination:<identity>:verified; の証拠が含まれます。再帰尺度は termination-measure-definedness と termination-decrease、ループ尺度は termination-loop-measure-definedness、termination-loop-nonnegative、後戻り辺がある場合の termination-loop-decrease を追加します。verified だけでは停止性を保証しません。プレイグラウンドは、対象そのものの証拠を使って停止性を明示的に要約します。依存先だけの停止性では、選択した関数を認証できません。証明の証拠で元の記録を確認できます。失敗した対象や不確実な対象には、停止性を検証済みとは表示しません。これだけで定義を取り込んだ等式が使えるようになるわけではなく、再帰深度や資源枯渇からの自由も保証しません。仕様、再帰のガイド、ループのガイドを参照してください。

静的アサーション

値の契約には Refine(lambda ...) を使います。特定のソース位置で検査する命題には Assert を使います。

from typing import Annotated
from refinepy import Assert

def absolute(n: int) -> int:
    x = abs(n)
    x: Annotated[int, Assert(lambda value: value >= 0)]
    return x

対象は確実に束縛済みの関数ローカル変数で、注釈には初期化式を付けません。基底型は現在の値と一致する必要があります。その型の既存の Refine 述語も検査します。Assert メタデータ項目はちょうど1つです。アサーションの繰り返しは可能です。その後の代入に契約を設定したり、既存の宣言契約を置き換えたりはしません。

Assert(lambda v: P(v), using=lambda arg: lemma(arg)) は、補助する補題も指定します。両方の lambda リテラルは、現在の値を表す束縛名で始めます。追加の通常の必須引数は、lambda value, y: value < y のように、確実に束縛済みの現在のローカル変数を明示的に指定します。lambda ごとに依存リストは異なっても構いません。入口の入力ではなく現在の SSA 値を参照し、後の再束縛で確立済みの事実は更新されません。既定値、可変長・重複の束縛名、未解決の名前、自由変数としてのローカル取り込みは未対応です。using は、列挙した束縛名からの論理引数を使い、戻り値が細分化された None のソース補題を直接1回呼び出します。検証器は引数と事前条件を検査してから事後条件を取り込み、P を証明します。補題の閉包全体について独立した停止性が必要です。通常の部分正当性、外部の信頼されたモデル、ループ、相互再帰、循環したアサーションの証拠では不十分です。補題は、そこから P が導かれる、より強い命題や異なる命題を示しても構いません。

using がない場合、命題は現在の事実と受け入れ済みの定義の等式から導かれる必要があります。どちらも未検査の仮定を与えません。検査の失敗やソルバーの不確実性では検証済みになりません。ローカル注釈は Python で評価されないため、述語と補題の呼び出しに実行時のコストはありません。補助する関数は通常の実行可能な定義を保持します。

Assert は、束縛済みのローカル名の、引用されていない宣言のみの注釈に限ります。引数、戻り値、別名、モジュール注釈、入れ子の型、追加メタデータを持つ注釈には使えません。レポートには static-assertion の証明義務と static-lemma: の依存の証拠が含まれます。健全性と束縛規則は仕様を参照してください。

定義を取り込む関数と補題

トップレベル関数に括弧なしの @reflect を付けると、検査済みの定義を述語とアサーションで使えます。定義からは、通常のインポートや再エクスポートを含め、他の定義を取り込む関数を呼び出せます。デコレーターは、実行を変えずに元の関数を返します。

定義にはローカル代入、平坦なアンパック、アサーション、if/elif/else 分岐、return、必要に応じて docstring を使えます。値のない return と末尾への到達は、通常の None の型付けに従います。細分化のない対応する入力・結果注釈には、スカラー、None、省略可能値、固定長の積、マッピングを含む対応コンテナーがあります。固定した位置引数・キーワード引数のシグネチャと、対応する不変のリテラル既定値も使えます。構築、積の操作、リストの連結・スライス、省略可能値の検査・内容の取り出し、マッピングの所属・参照・get、既存のスカラー操作、不変定数を使えます。呼び出し側の証明で定義を使う前に、ソース本体を検査し、評価されるすべての読み取り、省略可能値の内容の取り出し、除数が、入力領域全体で安全だと証明する必要があります。

細分化されたシグネチャ（入れ子の契約を含む）、事前条件、ループ、コンテナーへの書き込み、消去される証明呼び出し、相互再帰、ジェネリック、定義を取り込まない呼び出し、信頼された外部呼び出しは除外します。定義の連鎖が深さ32を超えるか、展開後のシリアライズした項が 128 KiB を超えると unsupported になります。文の CFG 展開も128辺に制限します。破棄した計算とアサーションの検査も、元のソース本体の証明義務として残ります。再帰シグネチャには次節の制限が適用されます。

定義を取り込む呼び出しは、注釈、requires、ループ不変条件、アサーション、本体で使えます。定義が引数を無視する場合でも、すべての引数の評価を検査します。通常の関数契約だけでは、論理で呼び出せる関数にはなりません。

補題は、戻り値の細分化で命題を記述する通常の検査対象関数です。多くの場合 Annotated[None, Refine(lambda _, x: ...)] を使います。本体はその命題を証明する必要があります。検証済みの補題を呼び出すと、その正常に戻る場合の契約を呼び出し側で使えます。明示的な decreases 尺度を持つ、戻り値が細分化された None の再帰補題は、後述する制限付きの帰納規則に対応します。例はガイド、検証の境界は仕様を参照してください。

再帰定義の取り込み

定義を取り込む関数は、宣言名で自身を呼び出せます。積、省略可能値、対応するコンテナーを含む、細分化のない対応する入力・結果型を使い、本体にループと事前条件を置かず、整数の decreases 尺度を明示します。ドライバーは、呼び出し側の証明でテンプレートを使う前に、元の自己呼び出しを検証し、減少を独立に検査します。他の全呼び出し先も検証済みで停止する必要があります。受け入れに失敗したり不確実だったりすると、呼び出し側の等式を使えません。

再帰定義の添字アクセスは、分岐のガードのもとで、元の本体の安全性検査に通る必要があります。呼び出しは、正規化した未解釈の関数識別を保持します。各問い合わせは、受け入れ済みの1段階の基礎的な定義等式を、スカラーのみのシグネチャなら8層、コンテナーを含めば3層まで追加します。帰納補題の問い合わせは、1層と検査済みの自己呼び出し契約を使います。これらは局所的な具体化であり、全称量化した再帰定義の公理ではありません。

等式は、積のフィールドと省略可能値のタグを再帰的に保持します。シーケンス結果は長さと有効な要素、マッピング結果は領域と存在する値を比較します。引数のガードと結果の事実は、有効な入れ子のスナップショットと文字列の観測を保持します。内部の等価関係が、ソースのマッピングや抽象シーケンスの比較を可能にするわけではありません。lambda の配列引数は領域全体の正確な別名参照を使い、スコープを持つ map/要素の適用は未解釈のままです。問い合わせは64個の等式と 128 KiB の基礎等式を許可します。既定の展開が大きすぎる場合は1層で再試行し、それでも予算を使い切ると analysis-limit を伴う unknown になります。

関数適用を含む充足可能な問い合わせも、関数の解釈を再構築しないため unknown になります。偽の等式の一部も含まれます。保存する1段階の定義と非循環の展開は 128 KiB、定義の依存先は32の上限を保持します。再帰の有限展開を受け入れる前の検査には、シリアライズした項について別の 4 MiB 予算があります。各置換と組み立て結果を検査し、超過は unsupported にします。展開した項は破棄し、証明の問い合わせは、上記の別の上限を持つ基礎等式を使います。フィボナッチの例（examples/fibonacci/README.md）は、この前検査で分岐する漸化式と検査済みの帰納的加法補題を受け入れます。pair 内の静的アサーションで直接特殊化し、添字の上限なしで高速倍加法の両方の結果を証明します。相互再帰、別名を介した自己呼び出し、複合型のコンテナー要素は引き続き除外します。非再帰の定義の取り込みは厳密です。

受け入れに成功すると、reflection:<identity>:verified recursive definition; に unfolding depth=<depth>; residual calls uninterpreted を伴う証拠と、termination: の証拠を記録します。worker プロトコル v17 は、構造的な複合コンテナー値と入れ子の要素の証拠に対応し、完全なモデルを検証します。入れ子の条件は、別々の字句的な束縛名と再帰的な観測検査を保持します。文字列はマッピングのキーを含め、完全なコードポイント列を使います。Python のコンテナー要素には対応する複合型を使えます。レポートスキーマ v3 は変わりません。ガイド、再帰リストの例、仕様を参照してください。

帰納補題

細分化された None の結果と、整数または辞書式の decreases 尺度を明示した直接再帰関数は、整礎帰納法で戻り値の命題を証明します。追加の指示は不要です。各自己呼び出しの引数と事前条件を検査し、宣言した戻り値の命題を局所的な帰納仮説として使い、基底ケースと再帰のすべての return を証明します。すべての呼び出し結果の要約を消去して、厳密な非負の減少を独立に証明します。依存先はすべて独立に検証済みで停止する必要があり、ループには検査済みの尺度が必要です。定義の取り込みは別に受け入れ、その基礎等式が補題の証明に入る前に検査します。

成功した証明には induction:<identity>:verified return proposition; に checked integer descent at every self-call を伴う証拠と、termination: の証拠が付きます。証拠は呼び出し側とキャッシュ利用にも伝わります。失敗した証明や不確実な証明は、帰納の成功も再利用可能なキャッシュ項目も公開しません。尺度のない補題は、正常に戻る場合の部分正当性を保持し、帰納の証拠は持ちません。分岐ごとの明示的な return は、合流点で結論の出ない候補述語推論を避けられます。自動帰納探索、相互帰納、任意の帰納的データ型の機能はありません。ガイドと仕様を参照してください。

コンテナーと省略可能値

要素の契約とコンテナーの契約は、異なる階層に適用します。Sequence[Nat] はすべての要素を制約します。以下の外側の述語は、添字が安全になるよう、要素が少なくとも1つあることを要求します。

NonEmptyNats = Annotated[Sequence[Nat], Refine(lambda xs: len(xs) > 0)]

def first(xs: NonEmptyNats) -> Nat:
    return xs[0]

シーケンスの読み取りには範囲内の添字が必要で、負の添字にも対応します。要素の細分化は、有効なスナップショットの領域全体に適用します。lambda の引数は局所的な束縛で、入れ子の論理計算もそのスコープを保持します。辞書の読み取りにはキーの存在が必要です。所属検査で参照をガードするか、get を使って省略可能な結果を処理してください。

from collections.abc import Mapping

def port_or_zero(ports: Mapping[str, Nat]) -> Nat:
    port = ports.get("http")
    if port is None:
        return 0
    return port

T | None と Optional[T] は、不在の検査と型の絞り込みに対応します。コンテナーは、積、省略可能値、入れ子のコンテナーを含む、対応する要素や値を持ちます。排他的なローカルリストの認証があれば、単独の append / extend、+=、整数の要素代入にも対応します。入力や共有リストへの書き込み、pop、スライス代入、辞書の更新は未対応です。排他的なローカルリストを参照してください。

リストを返すソースヘルパーは、検査済みの確保証明書を移譲できます。呼び出し側は、1つのローカル名で新しい結果に追加・拡張・更新できます。すべての return と代入は確保元の情報を保つ必要があり、両分岐と全ジェネリック特殊化を検査します。内容が等しいという契約だけでは所有権を確立できません。依存先の失敗、借用・混在した結果、根拠のない再帰の証明書サイクル、信頼されたモデルの確保に関する主張では書き込みを正当化できません。抽象 Sequence と省略可能な結果は証明書を移譲しません。入力と使用中のイテレーターの保護は継続します。証明書の探索は、1回につき異なるソース関数を最大64個訪問し、上限で保守的に停止します。レポートは、依存先の検証成功後にのみ ownership:<identity>:fresh-list-result; checked source allocation and aliases を公開します。この証拠は停止性を意味しません。ガイドを参照してください。

固定長タプルを返すソースヘルパーは、代わりに分離証明書を確立できます。到達可能な可変コンテナーがすべて確保され、各フィールドの参照グラフが互いに交わらないことを示します。直接の平坦なアンパック（left, right = split(xs)）でリストへの書き込みが許可されます。転送、インポートしたヘルパー、定義を取り込む呼び出し、全ジェネリック特殊化は、検査済みの依存を保持します。条件付き結果は、すべての選択肢の認証が必要です。同じ参照の繰り返し、借用フィールド、入れ子の共有は分離を妨げます。タプルの先行保存、フィールドの取り出し、入れ子のアンパックでは所有権を移せません。成功したレポートは ownership:<identity>:isolated-product-result; checked source allocations and disjoint fields を公開します。同じ64関数の探索上限が適用され、ループの確保履歴には64回の収束上限があります。ガイドの例を参照してください。

入れ子のコンテナーでは、リスト結果の証明書は外側のリストのみを記述します。新しく保存する要素に、別の書き込み済みローカルリストを残してはいけません。内側のリストを取り出しても排他性は確立しません。リストの等価比較は、スカラー、省略可能値、積、リストの要素を再帰的に許可します。抽象 Sequence とマッピングの要素は、積の内部に入れ子になっていても比較を妨げます。

再帰的に比較可能な要素のソートが一致すれば、リスト内容の等価比較では要素の細分化が異なっても構いません。例えば list[Nat] と list[int] を比較できます。これは、細分化のないリストを細分化された書き込み可能リストに代入できるという意味ではありません。連結には、引き続き一致する要素契約が必要です。ローカルリストの例は、厳密な範囲構築、偶数の完全かつ安定した抽出、他のすべての位置を保持する置換を証明します。仕様を参照してください。

ループとアサーション

if、while、対応する for ループは、通常の Python として使います。自動推論でループの性質を示せない場合、invariant(lambda ...) をループ直前に置きます。lambda の束縛名は、関数入口の値ではなく、現在のループ入口のローカル変数を指定します。停止性を要求するには decreases(lambda ...) を1つ使います。信頼された補助パッケージの識別は、インポート、別名、再エクスポートを通して解決します。

これらの式文は、位置引数でちょうど1つの lambda リテラルを受け取ります。名前付き callable、既定値、可変長の束縛名、キーワード引数はエラーです。連続するマーカーは、同じブロックの次のループに付属します。別の文を挟むと切り離され、エラーになります。空行と通常のコメントは挟めます。マーカー呼び出しは実行時に lambda を作りますが、呼び出したり契約を強制したりはしません。ソースの呼び出し依存にもなりません。旧不変条件コメント形式は非推奨ですが、互換性のため受け入れます。

from refinepy import invariant, decreases

def count_to(n: Nat) -> Annotated[int, Refine(lambda result, n: result == n)]:
    i = 0
    invariant(lambda i, n: 0 <= i <= n)
    decreases(lambda i, n: n - i)
    while i < n:
        i += 1
    return i

不変条件はループ前と各反復後に成立する必要があります。検査されるものであり、未検査の仮定として受け入れません。assert 条件も証明義務で、次節の述語言語を使う必要があります。

対応する形式と制限

ソルバーモデルの再構築は、配列の既定値、書き込み、認証された区分定数領域を完全に保持します。ネイティブ配列ごとに書き込み4,096個、構造の深さ128、問い合わせの束縛ごとに復号65,536ステップまで許可します。文字列も1文字列あたり4,096コードポイントまで完全に再構築し、マッピングのキーは文字列の内容で比較します。未対応の表現や制限の超過は unknown になり、サンプリングした反例にはしません。モデル検証を参照してください。モデルの検査は、保存表現と観測可能な値を区別します。不在の省略可能値の内容や領域外の項目も有効な型と数値形式が必要です。一方、ソース領域の制約は存在状態と領域のガードに従います。

ここで「対応」とは、列挙する制限のもとで形式を受け入れることです。その形式で書いたすべての性質を証明できるという保証ではありません。

述語式と組み込み関数

述語は bool を返し、宣言された型と確立した契約のもとで安全に評価できる必要があります。例えば len(xs) > 0 and xs[0] >= 0 のような短絡ガードで、読み取りを正当化できます。

式 許可する使い方
リテラル、lambda の束縛名、不変のスカラー定数 任意のグローバル変数の読み取りや代入は不可
整数算術と比較 変数同士の乗算、除算・剰余を許可。除数が0でないことは、先行する短絡ガードや入口の事実から導く必要あり
and、or、not、条件式 対応する真偽変換と互換性のある値型。最終的な述語は bool
len(value) 文字列、モデル化したシーケンス、固定長タプル。マッピングは不可
xs[i]、mapping[key]、key in mapping 読み取り前に境界やキーの存在を証明。固定長タプルのフィールド添字はリテラル
mapping.get(key[, default]) 文字列キーと互換性のあるスカラーまたは省略可能型の既定値
abs(x)、min(x, y)、max(x, y) 整数引数。min / max は位置引数をちょうど2つ取る

モデル化したリストの述語では、リストリテラル、+、==、!=、定数ステップのスライスを許可します。空リストには文脈からの要素型が必要です。等価比較は長さとすべての有効な要素を比較し、領域外の配列値を無視します。内部のスナップショット制約は完全な配列の等価関係を保持します。ガイドのリスト等式とリストモデルを参照してください。

タプルリテラル、連結、静的スライスも、述語と消去される補題の引数で許可します。比較結果が静的に分かる場合や、スライスがフィールドを選ばない場合も、各フィールドが安全である必要があります。述語内では、定義を取り込まないユーザー定義述語の呼び出し、明示的な量化、マッピング構築、内包表記を許可しません。本体でリテラルや呼び出しに対応していても、述語で使えるとは限りません。sum、all、any、sorted、isinstance、int / bool / str による変換には対応するモデルがありません。第三者ライブラリーの API は、既定では未対応です。

結果の適用範囲

結果の冒頭には、選択した関数の 検証済み、要確認、失敗 の件数が表示されます。要確認は unproved、unknown、unsupported、失敗は counterexample、error をまとめたものです。個別の意味は各カードに残ります。エラーは必ずしもソースのバグを意味しません。レポート全体の診断は別に表示され、診断がある場合は「すべて検証済み」にはなりません。各カードには短い結論と、別の停止性の要約があります。検証の詳細を展開すると、ソルバーのコスト、検証した範囲、推論した不変条件、ソースの依存先、所有権の記録を含む証明の証拠を確認できます。JSON レポート全文には完全なレポートが残ります。

verified は、契約を満たす入力と、モデル化した組み込み実行環境に適用します。モデル化した実行時エラーと、正常に戻る場合の契約を検査します。停止性は、尺度付きで受け入れた呼び出しの閉包についての追加の証拠です。その証拠を得るには、直接再帰に検査済みの整数または辞書式の尺度が必要で、各ループにも独自の尺度が必要です。通常の Python 実行時には、注釈は契約を強制しません。

プレイグラウンドは、Python を実行せずに1つのモジュールを読みます。パッケージ解決と外部モデル登録はネイティブのワークフローで行います。内部では refinepy が性質の候補を推論し、Z3 で証明義務を検査します。

境界ケースの詳細は Python 対応表と仕様を参照してください。このページはそれらの概要であり、対応する部分集合を拡張するものではありません。
