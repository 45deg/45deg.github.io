Reference

refinepy checks contracts on annotated Python 3.12 functions. The examples below show the supported writing patterns and share the imports and aliases introduced below. The tables summarize their main limits. For editor controls and result statuses, see Guide.

The numerical playground contains one basic range contract and examples of Fibonacci, integer square root, series summation, exact rational rounding and signed division. See the example guide for numerical illustrations, assumptions and failing edits. Sources are copied verbatim from maintained Python files; each result retains its own termination evidence.

Container-oriented examples remain in the repository and regression suite. The binary-search proof checks complete search correctness and termination for arbitrary sorted lists; the short contract exercises cover allocation and window reading. General recursive-specification queries can still be inconclusive.

The playground header has an EN / JP switch for English and Japanese. It translates controls, example names, editor search controls and result summaries entirely in the frontend. Switching preserves the source, undo history, selector, current run and existing results. The language preference is saved locally when browser storage is available; English is the default. Python samples, raw verifier diagnostics, proof records, stage identifiers and JSON stay in their original form. Guide and Reference content is available in both languages. Their Python code blocks remain identical. Linked technical documents under docs/ remain in English. The three header pages use client-side navigation without reloading the editor. Direct .html URLs, section links and browser Back/Forward are supported; refreshing still resets the source. Documentation load failures are shown explicitly.

Value contracts

Attach Refine(lambda ...) metadata to a type with Annotated. The lambda’s first parameter is the value being constrained. Multiple Refine predicates are combined with and.

from refinepy import Refine
from typing import Annotated

Nat = Annotated[int, Refine(lambda v: v >= 0)]

def increment(x: Nat) -> Annotated[int, Refine(lambda result, x: result == x + 1)]:
    return x + 1

x: Nat requires a nonnegative input. The return contract requires the result to be exactly one greater than the input. Additional lambda parameters name function inputs: a parameter contract may refer to earlier parameters, and a return contract may refer to any parameter. They denote values at function entry, even if the body later reassigns those names.

from collections.abc import Sequence

def at(
    xs: Sequence[int],
    i: Annotated[int, Refine(lambda v, xs: 0 <= v < len(xs))],
) -> int:
    return xs[i]

Aliases and local variable contracts use unary predicates. A local declaration such as count: Nat = 0 requires every later assignment to count to satisfy Nat; a parameter contract constrains its entry value only. All function parameters and returns need type annotations. Local types can be inferred.

Literal contracts and fixed tuples

Literal becomes a base type plus a contract restricting its allowed values. Use nonempty sets of int, bool, str or None literals, all with the same base type. Signed integers, static aliases and quoted annotations are supported. Combine Literal with Annotated, optional payloads, tuple fields and scalar container elements under their usual restrictions.

from refinepy import Refine
from typing import Literal

Mode = Literal["read", "write"]

def switch(mode: Mode) -> Mode:
    return "write" if mode == "read" else "read"

def reverse_pair(pair: tuple[Literal[0, 1], Mode]) -> tuple[Mode, Literal[0, 1]]:
    return pair[::-1]

Mixed bases (including int/bool), computed/named arguments, enums and nested Literal applications are unsupported. Integer Literal uses the existing numeric embedding: True satisfies Literal[1]; Literal[True] requires bool and excludes integer 1. Contracts are checked on assignments, returns and call arguments; defaults are base-checked at definition and refinement-checked when a call uses them.

Fixed tuples support ==/!= in bodies and predicates. Equality is fieldwise, with numeric bool/int comparisons. Optional fields compare their tags and present payloads, nested tuples compare recursively, and list fields compare valid-domain contents with matching recursively comparable element sorts. Mapping/abstract-sequence field equality and mismatched list element sorts are unsupported. Different arities or unrelated scalar field types are unequal. Both operands are evaluated once, including empty products. Tuple literals and a + b construct fixed products in bodies and predicates. Slicing preserves the selected field types and accepts static integer or omitted/None bounds and a nonzero static step, including reversal and clipped bounds. Empty results still evaluate the source and check its obligations. Dynamic product slice bounds remain unsupported. Tuple ordering is lexicographic over the common fields, followed by arity for an equal prefix. Common fields must be comparable integers/bools, strings, nested fixed tuples or matching None values. Optional, container and incompatible common fields are rejected even if an earlier field could decide the comparison. Both products are evaluated eagerly before comparing.

Tuple fields may recursively contain supported values, including None, optionals, other fixed tuples and supported containers. Contextual field types resolve empty container literals. Field and element refinements remain checked, and writable list/dict types remain invariant inside tuples. Product construction, concatenation and slicing preserve possible aliases: storing a written local list in a tuple is rejected, and extracting a list field does not certify fresh ownership. Directly unpacking a source result with a checked isolation certificate can transfer writable lists, as described below. Lists and mappings may contain products, optional values and nested supported containers. Reads preserve nested contracts. Extracting a nested list does not certify fresh ownership, and newly allocated outer lists may retain borrowed elements.

Function preconditions

Use @requires(lambda ...) for a relation across function inputs, including a parameter declared later. Multiple preconditions are combined.

from refinepy import requires

@requires(lambda xs, i: 0 <= i < len(xs))
def read_at(xs: Sequence[int], i: int) -> int:
    return xs[i]

The companion also exports ensures, decreases and reflect. import refinepy as rp and from refinepy import requires as pre work with @rp.requires(...) and @pre(...). Re-exports are resolved too; same-named user functions are unsupported. Use exactly one positional literal lambda for requires, ensures and decreases, with ordinary required positional parameters. Parentheses allow multiline conditions. @reflect takes no parentheses. Duplicate reflect or decreases markers are errors; decorator order does not change the contract.

These decorators preserve the original function and its type. They never execute predicates or check contracts at runtime. Running the Python code requires the refinepy companion package; the verifier does not import the checked code. Decorator imports must be available before the function definition and cannot be inside TYPE_CHECKING. Other decorators remain unsupported. Loop invariant comments are deprecated; use ordinary marker calls as described below. The old function-comment forms are errors.

Calls must satisfy the callee’s parameter contracts and preconditions. Source callees are checked too; their postconditions become available to callers. A source function callable in a body is not automatically callable in a predicate.

Function postconditions

@ensures(lambda result, n: result == n + 1) adds a return refinement to a function annotated -> int. The first lambda parameter denotes the result; additional parameters name immutable function-entry inputs, regardless of source reassignment. For a None result, omit the result binder: @ensures(lambda n: proposition) on a function annotated -> None. A parameterless lambda: proposition is allowed for None results only. The return base annotation remains required; aliases use the same binding rules.

from refinepy import ensures

@ensures(lambda result, n: result == n + 1)
def increment(n: int) -> int:
    return n + 1

@ensures(lambda n: n + 0 == n)
def identity_lemma(n: int) -> None:
    return None

Multiple ensures decorators and existing return Refine metadata are conjoined. They use the same logical subset, independent definedness checks, return checks and caller contracts as annotated refinements. A postcondition cannot justify its own definedness or that of a sibling. Ordinary required literal-lambda parameters are mandatory; imports, aliases and re-exports follow the precondition rules. Decorator order does not change the contract. The companion never invokes these predicates or changes callable identity, type, annotations or runtime execution. Reflected definitions still require plain return contracts, excluding ensures. For a decreasing recursive None lemma, ensures supplies the same proposition as an annotated return refinement; see Inductive lemmas.

Termination measures

One @decreases(lambda n: expression) decorator may mark a top-level function. Lambda binders name entry parameters and the result must be int or a literal nonempty fixed tuple of plain integer components, with the predicate language’s purity restrictions. The measure must be defined under entry contracts and preconditions. At each direct self-call, bind arguments normally and prove measure definedness and strict lexicographic descent. Every current and next component must be nonnegative; for a scalar this is 0 <= next < entry. The first unequal tuple component must decrease; later components can reset. Empty/nested tuples, boolean components and dynamic tuple construction are errors. A base case need not have a nonnegative measure. max(n, 0) and len(xs) work. Local reassignment does not change the function-entry measure.

Loops use a preceding ordinary decreases(lambda ...) call, optionally with invariant(lambda ...) calls. Every taken iteration snapshots a defined, nonnegative measure over bound source header locals, before binding a for target. Every normal or continue back edge must establish definedness, nonnegativity and strict scalar/lexicographic decrease from that snapshot. break, return and zero trips require no decrease. Even the final back edge must have a defined nonnegative next measure; max(n - i, 0) can prevent underflow. Each nested loop needs its own measure. Initially unbound iteration targets and hidden iterator counters cannot be lambda binders.

All callees must independently terminate. Trusted models and mutual recursion remain unsupported. A requested proof requires measures on every loop, including unreachable loops. The separate descent proof ignores all call-result contracts and rechecks fixed invariant definedness, initiation and preservation. Thus result-dependent descent or invariants may remain unproved. Every generic specialization must pass before evidence is published.

Nonrecursive functions with no loops or with all loops explicitly measured also obtain termination evidence when their complete checked call closure terminates. Reports include termination:<identity>:verified; evidence. Recursive measures add termination-measure-definedness and termination-decrease; loop measures add termination-loop-measure-definedness, termination-loop-nonnegative and termination-loop-decrease (when a back edge exists). A verified status alone does not promise termination. The playground shows an explicit termination summary using the exact target’s evidence; termination of a dependency alone does not certify the selected function. Proof evidence exposes the underlying records. Failed or uncertain targets never display verified termination. This does not by itself supply reflected equations or guarantee freedom from recursion-depth or resource exhaustion. See the specification, recursive Guide and loop Guide.

Static assertions

Use Refine(lambda ...) for a value contract. Use Assert for a proposition checked at a particular source position:

from typing import Annotated
from refinepy import Assert

def absolute(n: int) -> int:
    x = abs(n)
    x: Annotated[int, Assert(lambda value: value >= 0)]
    return x

The target must be a definitely bound function local and the annotation must have no initializer. Its base type must match the current value; existing Refine predicates on that type are also checked. Exactly one Assert metadata item is permitted. Repeating assertions is allowed. They do not install a contract on later assignments or replace an existing declaration contract.

Assert(lambda v: P(v), using=lambda arg: lemma(arg)) additionally supplies a supporting lemma. Both literal lambdas start with a binder denoting the current value. Additional ordinary required parameters explicitly name definitely bound current locals; for example, lambda value, y: value < y. The lambdas can use different dependency lists. They observe current SSA values rather than entry inputs, and later rebinding does not update an established fact. Defaults, variadic/duplicate binders, unresolved names and free local captures are unsupported. using contains one direct refined-None source lemma call with logical arguments from its listed binders. The verifier checks its arguments and preconditions before importing the postcondition to prove P. It requires independent termination of the entire lemma closure; ordinary partial correctness, external trusted models, loops, mutual recursion and circular assertion evidence are insufficient. A lemma can establish a stronger or different proposition from which P follows.

Without using, the proposition must follow from current facts and admitted reflected equations. Neither form supplies an unchecked assumption. Failed checks and solver uncertainty cannot verify. Local annotations are not evaluated by Python, so the predicate and lemma calls incur no runtime cost. Supporting functions keep their ordinary executable definitions.

Assert is restricted to unquoted, declaration-only annotations of bound local names. It is not valid in parameters, returns, aliases, module annotations, nested types or annotations with additional metadata. Reports include static-assertion obligations and static-lemma: dependency evidence. See the specification for soundness and binding rules.

Reflected functions and lemmas

Use bare @reflect on a top-level function to make its checked definition available in predicates and assertions. Definitions can call other reflected functions, including through regular imports and re-exports. The decorator returns the original function without changing its execution.

Definitions may use local assignments, flat unpacking, assertions, if/elif/else branches and returns, with an optional docstring. Bare returns and fallthrough use the usual None typing. Plain supported input/result annotations include scalars, None, optionals, fixed products and supported containers (including mappings). Fixed positional/keyword signatures and supported immutable literal defaults are supported. Construction, product operations, list concatenation/slicing, optional tests/projections, mapping membership/lookup/get, existing scalar operations and immutable constants are permitted. Every evaluated read, optional projection and divisor must be proved safe over the entire input domain by checking the source body before caller proofs use its definition. Refined signatures (including nested contracts), preconditions, loops, container writes, erased proof calls, mutual recursion, generics and unreflected or trusted external calls are excluded. Definition chains deeper than 32 or expanded serialized terms above 128 KiB produce unsupported; statement CFG expansion is also limited to 128 edges. Checks from discarded computations and assertions remain obligations in the original source body. Recursive signatures retain the limits below.

Reflected calls work in annotations, requires, loop invariants, assertions and bodies. All argument evaluations are checked, even if the definition ignores an argument. Ordinary function contracts do not make a function callable in logic.

A lemma is an ordinary checked function whose return refinement states a proposition, often using Annotated[None, Refine(lambda _, x: ...)]. Its body must prove that proposition. Calling a verified lemma makes its normal-return contract available to the caller. Recursive refined-None lemmas with an explicit decreases measure support the restricted induction rule below. See the Guide for an example and the specification for the verification boundary.

Recursive reflection

A reflected function may call itself by its declaration name with plain supported input/result types, including products, optionals and supported containers, a loop-free body, no preconditions, and an explicit integer decreases measure. The driver verifies raw self-calls and independently checks descent before any caller proof uses its template. All other callees must verify and terminate too; failed or uncertain admission blocks caller equations.

Indexing in recursive definitions must pass raw-body safety checks under its branch guards. Calls retain a canonical uninterpreted function identity. Each query adds admitted one-step ground definition equations, up to eight layers for scalar-only signatures or three when a signature contains a container. Inductive lemma queries use one layer and their checked self-call contracts. These are local instances, not universally quantified recursive defining axioms.

Equations recursively preserve product fields and optional tags. Sequence results compare lengths and valid elements; mapping results compare domains and present values. Argument guards and result facts preserve valid nested snapshots and string observations. Internal equality does not enable source mapping or abstract-sequence comparison. Lambda array arguments use exact full-domain aliases; scoped map/element applications are left uninterpreted. Queries allow 64 equations and 128 KiB of ground equations; oversized default expansion retries one layer, and exhausting that budget returns unknown with analysis-limit. Satisfiable queries containing applications also return unknown, since their function interpretations are not reconstructed. This includes some false equations. Stored one-step definitions and acyclic expansions retain their 128 KiB bound; definition dependencies remain limited to 32. Recursive bounded-expansion admission preflight has a separate 4 MiB serialized-term budget. It checks each substitution and assembled result, and excess produces unsupported. Its expanded term is discarded; proof queries still use the separately bounded ground equations above. The Fibonacci example (examples/fibonacci/README.md) uses this preflight to admit a branching recurrence and a checked inductive addition lemma, specialized directly in pair by a static assertion, to prove both fast doubling results without an index upper bound. Mutual recursion, aliased self-calls and composite container elements remain excluded. Nonrecursive reflection remains exact.

Successful admission records reflection:<identity>:verified recursive definition; evidence with unfolding depth=<depth>; residual calls uninterpreted, alongside termination: evidence. Worker protocol v17 supports structural composite container values and nested element evidence, and validates their complete models. Nested conditions retain separate lexical binders and recursive observation checks. Strings use complete code-point sequences, including as mapping keys. Python container elements may use supported composite types; report schema v3 is unchanged. See the Guide, recursive list example and specification.

Inductive lemmas

A directly recursive function with a refined None result and explicit integer or lexicographic decreases measure proves its return proposition by well-founded induction. No additional directive is required. Check the arguments and preconditions of every self-call, use its declared return proposition as the local induction hypothesis, and prove all base and recursive returns. Independently prove strict nonnegative descent with every call-result summary erased. All dependencies must independently verify and terminate; any loops need checked measures. Reflected definitions are admitted separately, before their ground equations can enter the lemma’s proof.

Successful proofs carry induction:<identity>:verified return proposition; evidence with checked integer descent at every self-call, plus termination: evidence. Evidence propagates to callers and cache hits. Failed or uncertain proofs publish neither induction success nor reusable cache entries. Lemmas without a measure retain normal-return partial correctness and have no induction evidence. Explicit branch returns can avoid inconclusive qualifier inference at joins. There is no automatic induction search, mutual induction or arbitrary inductive-data-type facility. See the Guide and specification.

Containers and optional values

An element contract and a container contract apply at different levels. Sequence[Nat] constrains every element; the outer predicate below requires at least one element so the index is safe.

NonEmptyNats = Annotated[Sequence[Nat], Refine(lambda xs: len(xs) > 0)]

def first(xs: NonEmptyNats) -> Nat:
    return xs[0]

Sequence reads require in-bounds indices; negative indices are supported. Element refinements apply throughout the valid snapshot domain. Their lambda parameters are local bindings; nested logical computations preserve that scope. Dictionary reads require the key to be present. Guard a lookup with membership, or use get and handle its optional result.

from collections.abc import Mapping

def port_or_zero(ports: Mapping[str, Nat]) -> Nat:
    port = ports.get("http")
    if port is None:
        return 0
    return port

T | None and Optional[T] support absence checks and narrowing. Containers have supported elements or values, including products, optionals and nested containers. Certified exclusive local lists also support standalone append/extend, += and integer item assignment. Input or shared-list writes, pop, slice assignment and dictionary updates remain unsupported. See exclusive local lists.

Source helpers returning lists may transfer a checked allocation certificate. A caller can append to, extend or update the fresh result under one local name. Every return and assignment must preserve allocation provenance; both branches and all generic specializations are checked. Contracts asserting equal contents cannot establish ownership. Failed dependencies, borrowed/mixed results, ungrounded recursive certificate cycles and trusted model allocation claims cannot justify writes. Abstract Sequence and optional results do not transfer certificates. Input and live-iterator protections remain in force. Certificate discovery visits at most 64 distinct source functions per discovery and stops conservatively at that bound. Reports expose ownership:<identity>:fresh-list-result; checked source allocation and aliases only after successful dependency verification; this evidence does not imply termination. See the Guide.

A source helper returning a fixed tuple may instead establish an isolation certificate: all reachable mutable containers are allocated and each field’s reference graph is disjoint from the others. Direct flat unpacking (left, right = split(xs)) then permits list writes. Forwarding, imported helpers, reflected calls and all generic specializations retain checked dependencies. A conditional result must have certified alternatives. Repeated references, borrowed fields and nested sharing prevent isolation. Saving the tuple first, extracting a field, or nested unpacking does not transfer ownership. Successful reports expose ownership:<identity>:isolated-product-result; checked source allocations and disjoint fields. The same 64-function discovery bound applies; loop allocation histories have a 64-round convergence bound. See the Guide example.

For nested containers, a list-result certificate describes the outer list only. Newly stored elements must not retain another written local list, and extracting an inner list does not establish exclusivity. List equality recursively permits scalar, optional, product and list elements; abstract Sequence and mapping elements block it, even when nested inside a product.

List content equality permits different element refinements when recursively comparable element sorts match, for example list[Nat] compared with list[int]. This observation does not permit assigning a plain list to a refined writable list. Concatenation still requires matching element contracts. The local-list example proves exact range construction, complete stable even filtering and replacement with all other positions preserved; see the specification.

Loops and assertions

Use if, while and supported for loops as ordinary Python. When automatic inference cannot establish a loop property, place invariant(lambda ...) calls directly before the loop. Lambda binders name current header locals, not their function-entry values. Use one decreases(lambda ...) call to request termination. Resolve trusted companion identities through imports, aliases and re-exports. These expression statements take exactly one positional literal lambda; named callables, defaults, variadic binders and keyword arguments are errors. Consecutive markers attach to the next loop in the same block; another statement detaches them and is an error. Blank lines and ordinary comments may intervene. The marker calls create lambdas at runtime but never invoke them or enforce their contracts. They are not source-call dependencies. The legacy invariant comment form is deprecated and remains accepted for compatibility.

from refinepy import invariant, decreases

def count_to(n: Nat) -> Annotated[int, Refine(lambda result, n: result == n)]:
    i = 0
    invariant(lambda i, n: 0 <= i <= n)
    decreases(lambda i, n: n - i)
    while i < n:
        i += 1
    return i

The invariant must hold before the loop and after every iteration. It is checked, not accepted as an unchecked assumption. An assert condition is also a proof obligation; it must use the predicate language below.

Supported forms and limits

Solver model reconstruction retains complete array defaults, stores and certified piecewise-constant regions. It permits at most 4,096 stores per native array, structural depth 128 and 65,536 decoding steps per query binding. Strings are reconstructed completely, up to 4,096 code points per string; mappings use string contents as keys. Unsupported representations or exhausted limits produce unknown, never a sampled counterexample. See model validation. Model checks distinguish stored representation from observable values: absent optional payloads and out-of-domain entries still require valid types and number formats, while source-domain restrictions follow presence and domain guards.

“Supported” here means the form is admitted under the listed restrictions. It does not guarantee that every property written with that form can be proved.

Predicate expressions and built-ins

Predicates must produce a boolean and be safe to evaluate under the declared types and established contracts. Short-circuit guards can justify a read, for example len(xs) > 0 and xs[0] >= 0.

Expression Admitted use
Literals, lambda binders, immutable scalar constants No arbitrary global reads or assignments
Integer arithmetic and comparisons Variable multiplication and division/modulo are admitted; divisor nonzero must follow from earlier short-circuit guards or entry facts
and, or, not, conditional expressions Supported truth conversion and compatible value types; final predicate is boolean
len(value) Strings, modeled sequences and fixed tuples; not mappings
xs[i], mapping[key], key in mapping Prove bounds or key presence before the read; fixed-tuple field indices are literals
mapping.get(key[, default]) String keys and a compatible scalar/optional default
abs(x), min(x, y), max(x, y) Integer arguments; min/max take exactly two positional arguments

List literals, +, ==, !=, and constant-step slices are admitted in predicates for modeled lists. Empty lists need a contextual element type. Equality compares lengths and all valid elements, ignoring array values outside the domain; internal snapshot constraints retain full array equality. See the Guide list equation and the list model. Fixed-tuple literals, concatenation and static slicing are also admitted in predicates and erased lemma arguments. Every field must be safe even when a comparison has a statically known result or a slice selects no fields. No unreflected user-defined predicate calls, explicit quantifiers, mapping construction or comprehensions are admitted inside predicates. Body support for a literal or call does not imply predicate support. Built-ins such as sum, all, any, sorted, isinstance and conversions with int/bool/str have no supported model. Third-party library APIs are not supported by default.

Scope of a result

The results start with counts of Verified, Needs review and Failed selected functions. Needs review groups unproved, unknown and unsupported; Failed groups counterexample and error, whose individual meanings remain visible on each card. An error does not necessarily indicate a source bug. Report-level diagnostics appear separately and prevent an all-verified summary. Each card gives a short conclusion and a separate termination summary. Expand Verification details for solver costs, checked scope, inferred invariants, source dependencies and Proof evidence, including ownership records. Full JSON report retains the complete report.

A verified result applies to inputs satisfying the contracts and the modeled built-in runtime. It checks modeled runtime errors and normal return contracts; termination is additional evidence for admitted measured call closures. Direct recursion requires a checked integer or lexicographic measure, and every loop requires its own measure, to obtain that evidence. Annotations do not enforce contracts when ordinary Python code runs.

The playground reads one module without executing Python. Package resolution and external model registration belong to native workflows. Internally, refinepy infers candidate properties and checks proof obligations with Z3.

For exact edge cases, consult the Python support matrix and specification. This page summarizes those documents; it does not expand the supported subset.
