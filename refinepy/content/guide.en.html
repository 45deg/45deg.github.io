Write a contract

The repository’s binary-search example verifies a complete search contract and termination for arbitrary-length sorted lists, including duplicates. Checked inductive interval lemmas preserve membership as the interval shrinks; static assertions use those lemmas without executing them. See the specification.

Use Annotated to attach a predicate to a type. The first lambda parameter is the value being constrained. A return predicate can also name the function’s parameters to relate the result to its inputs.

from refinepy import Refine
from typing import Annotated

Nat = Annotated[int, Refine(lambda v: v >= 0)]

def increment(x: Nat) -> Annotated[int, Refine(lambda result, x: result == x + 1)]:
    return x + 1

This contract requires a nonnegative input and a result exactly one greater than that input. Try changing the return expression to x - 1 and verify again.

Verify string contents

Strings support content equality, length, concatenation, safe integer indexing and step-1 slicing in both bodies and predicates. Prove a read is in bounds; negative indices count from the end. Slices clip their bounds, and accept omitted or None bounds and an omitted, None or constant step of one.

from typing import Annotated
from refinepy import Refine, requires

@requires(lambda text: len(text) > 0)
def first(text: str) -> Annotated[str, Refine(lambda result: len(result) == 1)]:
    return text[0]

def append(left: str, right: str) -> Annotated[str, Refine(lambda result, left, right: len(result) == len(left) + len(right))]:
    return left + right

The model preserves every Python code point, including surrogates. String methods, f-strings and other slice steps remain unsupported. Ordering compares code points lexicographically; "a" < "aa" < "b". Fixed tuples also compare lexicographically when their common fields are comparable integers/bools, strings or nested tuples (with matching None fields allowed). String witnesses are reconstructed completely up to 4,096 code points; larger witnesses yield unknown. See the string model and support matrix.

Describe a complete tuple result

Use a tuple literal in a contract to describe all result fields together:

from refinepy import ensures

@ensures(lambda result, x: result == (x, x + 1))
def pair(x: int) -> tuple[int, int]:
    return x, x + 1

Tuple construction, concatenation and static slicing are available in preconditions, refinements, assertions and loop invariants. For example, result == pair_input[::-1] describes reversal of a fixed tuple. Fields can include optional values, nested tuples and lists or mappings with supported elements. Each field expression must be safe, even if a later slice is empty or equality is already false from a different field. Guard partial reads before constructing the tuple. See the Reference and tuple model.

A function can return two lists with a contract on the complete pair:

from typing import Annotated
from refinepy import Refine

def split_at(xs: list[int], i: int) -> Annotated[
    tuple[list[int], list[int]],
    Refine(lambda result, xs, i: result == (xs[:i], xs[i:])),
]:
    return xs[:i], xs[i:]

Expected field types also allow return [], [] for a tuple[list[int], list[int]] result. List elements themselves still have scalar types. A list extracted from a tuple is borrowed: extraction does not authorize updates. Return locally built lists directly after their writes; storing one in a tuple does not bypass the rule against aliases of written lists.

Multiply integer inputs

Integer multiplication accepts two variable operands in bodies and predicates. For example, a square is nonnegative for every integer input:

from refinepy import Refine
from typing import Annotated

def square(a: int) -> Annotated[int, Refine(lambda result: result >= 0)]:
    return a * a

Select square and verify. Changing result >= 0 to result > 0 produces a counterexample at a = 0. A product can use the dependent result contract Annotated[int, Refine(lambda result, a, b: result == a * b)]. Integer a *= b also accepts a variable right operand and checks any declared local contract after rebinding.

Nonlinear integer obligations can exceed the solver’s capabilities or configured limits and return unknown. Support does not guarantee a proof for every polynomial property. See Reference and the integer model.

Divide by an integer input

Use a precondition or a branch to establish a nonzero divisor. Both signs are supported, with Python floor rounding and remainder signs:

from refinepy import requires, ensures

@requires(lambda d: d != 0)
@ensures(lambda r, a, d: a == r[0] * d + r[1] and
    (0 <= r[1] < d if d > 0 else d < r[1] <= 0))
def divide(a: int, d: int) -> tuple[int, int]:
    return a // d, a % d

An unguarded variable divisor produces a failed definedness obligation if it can be zero. a // d if d else 0 is a supported safe alternative; //= and %= apply the same check. Predicates also need a guard, such as d != 0 and a % d == 0. Variable-divisor proofs can return unknown. See the integer model.

Build and update a local list

The maintained examples/local-lists/lists.py source contains the complete range, filter, replacement and exchange example. Paste it into the playground to verify it. The numerical menu includes Signed quotient and remainder.

The maintained examples/partition/partition.py proves an exact negative/nonnegative partition and safely updates both results without changing the input. Paste its source into the editor and verify with *.

Construct a fresh list under one local name. Its contents can then be updated while input lists retain their entry values:

from refinepy import requires, ensures

@requires(lambda xs, i: -len(xs) <= i < len(xs))
@ensures(lambda r, xs, i, value:
    len(r) == len(xs) and r[i] == value
    and r == xs[:i if i >= 0 else len(xs) + i] + [value]
        + xs[(i if i >= 0 else len(xs) + i) + 1:])
def replace(xs: list[int], i: int, value: int) -> list[int]:
    out = xs[:]
    out[i] = value
    return out

Standalone append and extend, and list +=, support result construction. Empty lists need an explicit local type, such as out: list[int] = []. Each added or replaced element must satisfy the element contract, including refinements such as nonnegativity or evenness. Whole-list local refinements are checked after every write. Loops may need explicit invariants/measures. Element refinements describe every valid element, not just the elements read by the function. Each refinement lambda binds its own element value.

The replacement contract preserves the complete prefix and suffix, including for negative indices. The local-list example also proves that build_range returns exactly 0 through n - 1, and evens returns every even input element in its original order with duplicates preserved. Reflected specifications and exact prefix invariants express these contracts without executing specification functions during construction. List equality accepts matching recursively comparable element sorts even when one side has a stronger element refinement. See the complete contracts.

Container elements can be tuples, optional values or other supported containers:

def coordinates() -> list[tuple[int, int]]:
    out: list[tuple[int, int]] = [(1, 2)]
    out.append((3, 4))
    assert out == [(1, 2), (3, 4)]
    return out

def missing_values() -> list[int | None]:
    out: list[int | None] = [None, 2]
    out[0] = 1
    assert out[0] is not None
    return out

Nested empty literals receive their type from a declared result, local annotation or typed adjacent list. Nested field and element refinements remain obligations. A newly allocated outer list does not give ownership of borrowed inner lists; reading rows[0] cannot justify modifying that list. Comprehensions can also construct supported composite elements:

def adjacent_pairs(xs: list[int]) -> list[tuple[int, int]]:
    return [(x, x + 1) for x in xs]

Each comprehension has one synchronous generator. Nested comprehensions have separate variable scopes; filters and multiple generators in one comprehension remain unsupported. Element construction must satisfy its contracts and be safe for every input element. An empty input does not evaluate the element expression. Reflected helper calls still require successful dependency verification.

Fresh list construction can be shared through checked source helpers:

from refinepy import ensures

@ensures(lambda result, xs: result == xs)
def copy(xs: list[int]) -> list[int]:
    return xs[:]

@ensures(lambda result, xs, value: result == xs + [value])
def append_copy(xs: list[int], value: int) -> list[int]:
    out = copy(xs)
    out.append(value)
    return out

The verifier checks the helper’s actual allocation and every source dependency. The same equality contract on return xs would not permit the caller’s write. Both branches must return fresh lists; a borrowed alternative prevents ownership transfer. Imported helpers and chains of certified calls are supported. Inferred call results retain their element refinements when updated.

A helper can also return two independent lists and transfer both through direct unpacking:

@ensures(lambda result, xs: result == (xs, xs))
def copies(xs: list[int]) -> tuple[list[int], list[int]]:
    return xs[:], xs[:]

@ensures(lambda result, xs: result == (xs + [1], xs + [2]))
def grow(xs: list[int]) -> tuple[list[int], list[int]]:
    left, right = copies(xs)
    left.append(1)
    right.append(2)
    return left, right

The certificate checks independent allocations, including references retained inside nested containers. Returning one list twice or returning an input does not qualify. Keep the unpacking at the call: saving the tuple in a local and then extracting its fields retains aliases and does not permit writes. The ownership rules describe forwarded, conditional, reflected and generic results. The repository example examples/partition/partition.py proves exact negative/nonnegative partitions, including order and duplicates, and updates both returned lists. Its prefix specification is total, and the loop has a checked decreasing measure.

Saving alias = out makes writes unsupported. Input lists and borrowed call results cannot become writable through assignment. A loop that updates out must iterate a stable input or a fresh copy such as out[:]. Ordinary iteration after construction is supported. pop, clear, slice assignment and nested mutation calls remain unsupported. See the ownership and write rules.

Fixed tuples and allowed values

Use Literal for a finite set of allowed scalar values. Fixed tuples retain contracts for each field and support equality, concatenation and static slices.

from refinepy import Refine
from typing import Literal

Mode = Literal["read", "write"]

def reverse_pair(pair: tuple[Literal[0, 1], Mode]) -> tuple[Mode, Literal[0, 1]]:
    return pair[::-1]

Literal arguments must share one base type. Tuple slice bounds and steps must be statically known integers (or omitted/None), with a nonzero step. See Reference for the exact limits.

Add a function precondition

Use an imported requires decorator for a relation across inputs. It can refer to any input, including one declared later, and can span several lines.

from refinepy import requires

@requires(
    lambda xs, i: 0 <= i < len(xs)
)
def read_at(xs: list[int], i: int) -> int:
    return xs[i]

import refinepy as rp and from refinepy import requires as pre also work. The decorators never execute predicates or check contracts during Python execution, and preserve the original function. Install the refinepy companion package to run decorated code. The verifier reads source without importing it. Use decorators for requires, reflect and decreases; their old comment forms are rejected. Loop invariants use ordinary invariant(lambda ...) calls; the comment form is deprecated. See Reference for the binding rules.

Comparison chains such as 0 <= i < len(xs) are supported. Split chains containing None, in or not in into separate boolean guards, for example left is None and right is None. Function defaults must be scalar/None literals or flat tuples of int/bool/str literals; nested tuples and None fields in tuple defaults are unsupported. See the supported forms and limits.

Write a return contract with ensures

Use ensures to write a return refinement above the function instead of inside Annotated. Keep the return base type in the function signature.

from refinepy import ensures

@ensures(lambda result, n: result == n + 1)
def increment(n: int) -> int:
    return n + 1

@ensures(lambda n: n + 0 == n)
def identity_lemma(n: int) -> None:
    return None

For a value result, the first lambda parameter denotes the result and later parameters name function-entry inputs. For a None result, all lambda parameters name entry inputs, so a proof function needs no dummy result parameter. Multiple ensures decorators and existing return Refine metadata must all hold. These predicates are checked statically and never run during Python execution. See Reference for the full rules.

Check recursive termination

Add an integer measure with decreases. Each recursive call must use a nonnegative measure strictly smaller than the measure on entry:

import refinepy
from refinepy import Refine
from typing import Annotated

Nat = Annotated[int, Refine(lambda v: v >= 0)]

@refinepy.decreases(lambda n: n)
def count(n: Nat) -> Annotated[int, Refine(lambda r, n: r == n)]:
    return 0 if n == 0 else 1 + count(n - 1)

Select count and verify. Changing count(n - 1) to count(n) fails the termination obligation. The measure can also use len(xs) for recursion over list slices. It refers to the original inputs even after local reassignment.

For more than one component, return a literal nonempty integer tuple. The first unequal component must decrease; later components may reset:

@refinepy.decreases(lambda n, m: (n, m))
def lex_count(n: Nat, m: Nat) -> int:
    if m > 0:
        return lex_count(n, m - 1)
    if n > 0:
        return lex_count(n - 1, 3)
    return 0

Every component must remain nonnegative at recursive calls. All source callees must independently terminate, and any loops need explicit measures as below. A function without this decorator can still verify its normal return contract without proving recursive termination. Successful checks add termination: evidence; Python recursion-depth and resource limits remain outside the guarantee. See Reference.

Check loop termination

Place ordinary invariant and decreases calls directly before the loop. Their lambda binders name current header locals. Consecutive invariants are conjoined; one measure may accompany them, in either order. These calls also work with ordinary Python type checkers. The companion never invokes the lambdas.

from typing import Annotated
from refinepy import Refine, invariant, decreases

Nat = Annotated[int, Refine(lambda v: v >= 0)]

def count_to(n: Nat) -> Annotated[int, Refine(lambda r, n: r == n)]:
    i = 0
    invariant(lambda i, n: 0 <= i <= n)
    decreases(lambda i, n: n - i)
    while i < n:
        i += 1
        if i % 2 == 0:
            continue
    return i

Select count_to and verify. The invariant establishes the header property by induction over iterations. The measure proves termination: it is nonnegative on each taken iteration and strictly decreases on both the normal and continue back edges. Changing the measure to i, or adding a path that continues without incrementing i, fails verification. An invariant without a measure proves only partial correctness and publishes no termination evidence for the loop.

Loop measures also accept tuples such as (n, m). Nested loops each need their own measure. Supported for loops use the same calls; source locals must be bound before the loop, so an initially unbound iteration target cannot be a binder. Measures are snapshotted before the body and before binding a for target. There is no decrease requirement on break, return or zero iterations. Every back edge must still have a defined nonnegative next measure, including the final iteration; max(n - i, 0) can keep a countdown total.

An independent termination check removes all call-result summaries and rechecks invariant initiation and preservation. A proof relying on a callee’s result contract can therefore remain unproved. All callees must independently terminate. Python executes the marker calls once before each loop is reached, but does not execute their predicate or measure bodies. See Reference and specification.

Prove an equation about a function

Mark a total scalar expression function with @refinepy.reflect to use its actual definition in a contract. A lemma can return None with the equation as its return refinement:

from __future__ import annotations
import refinepy
from refinepy import Refine
from typing import Annotated

@refinepy.reflect
def inc(x: int) -> int:
    return x + 1

def lemma(x: int) -> Annotated[None, Refine(lambda _, x: inc(inc(x)) == x + 2)]:
    return None

Select lemma and verify. Changing x + 2 to x + 3 makes the proof fail. Other checked functions can call a lemma to use its normal-return contract. Reflected definitions accept assignments, flat unpacking, assertions, branches and returns, with plain supported value annotations, including products, optionals and supported containers. Nested refinements and preconditions are excluded. Direct recursion has the additional requirements below. Recursive lemmas with checked descent can prove propositions by induction, as shown below. See Reference for the limits.

For example, a guarded mapping lookup can become a logical function:

@refinepy.reflect
def find_value(values: dict[str, int], key: str) -> int | None:
    if key not in values:
        return None
    result = values[key]
    return result

def check_lookup(values: dict[str, int], key: str) -> None:
    assert (find_value(values, key) is None) == (key not in values)

The verifier checks the lookup guard in find_value before using its definition in check_lookup. Loops and container writes remain unsupported in reflected bodies. Removing the guard fails verification even if a caller uses find_value(values, key) == find_value(values, key). Optional payload access and variable divisors require the same independent safety check.

Use a lemma without executing it

Function-local annotations are not evaluated by Python. A static Assert annotation lets verification use a checked lemma without adding a runtime call:

from typing import Annotated
from refinepy import Assert

def use_lemma(x: int) -> int:
    x: Annotated[int, Assert(
        lambda value: inc(inc(value)) == value + 2,
        using=lambda arg: lemma(arg),
    )]
    return x

Add this function to the inc and lemma example above. The verifier checks the lemma’s safety and termination, checks the actual arguments, then uses its postcondition to prove the assertion. Its postcondition does not have to match the assertion exactly. A nonterminating lemma cannot supply a static proof, even if its normal-return contract verifies.

Assert(lambda value: ...) without using checks the proposition from current facts. Both forms apply to an already bound local and leave future assignments unconstrained unless a declaration contract already applies. The first lambda binder receives the current value. Additional binders, such as lambda value, y: value < y, explicitly name currently bound locals. The using lambda can list its own local dependencies to pass several arguments to a lemma. Free local captures are unsupported. These binders use values at the assertion, even if an input was rebound; later changes do not update the established fact. Use Refine for contracts on inputs, results and local declarations. See Reference and the binary-search proof.

Reflect a recursive scalar function

Combine reflect with decreases to use a terminating recursive definition in a bounded equation:

from __future__ import annotations
import refinepy
from refinepy import Refine
from typing import Annotated

@refinepy.reflect
@refinepy.decreases(lambda n: max(n, 0))
def count(n: int) -> int:
    return 0 if n <= 0 else 1 + count(n - 1)

def bounded(n: Annotated[int, Refine(lambda v: 0 <= v <= 7)]) -> Annotated[
    None, Refine(lambda _, n: count(n) == n)
]:
    return None

Select bounded and verify. The source definition must independently pass its termination checks before its equations can be used. Changing the recursive argument to n fails that check, even for an otherwise trivial equation.

Scalar-only recursive reflected inputs and results must be plain int or bool, with one return expression and no preconditions. Calls expand through eight definition layers. Beyond that, calls remain uninterpreted; inconclusive queries return unknown, including some false equations. This supports bounded equations, while unbounded equations require an explicit inductive lemma. Recursive lists use a smaller unfolding bound, as shown below. See Reference.

Recursive reflected functions may also carry products and optional values:

@refinepy.reflect
@refinepy.decreases(lambda n: max(n, 0))
def carry(n: int, pair: tuple[list[int], int | None]) -> tuple[list[int], int | None]:
    if n <= 0:
        return pair
    return carry(n - 1, pair)

def check_carry(xs: list[int]) -> None:
    assert carry(1, (xs, None)) == (xs, None)

Mapping and sequence inputs/results are also supported. The verifier preserves optional presence and valid container contents through the recursive equations. Signatures containing containers use at most three definition layers by default; unbounded claims still need an inductive lemma or may remain unproved.

Reflect a recursive list function

A recursive function can take or return a plain list[int], list[bool], or list[str]. Use len(xs) as a decreasing measure and guard partial indexing:

from __future__ import annotations
import refinepy
from refinepy import Refine
from typing import Annotated

@refinepy.reflect
@refinepy.decreases(lambda xs: len(xs))
def reverse(xs: list[int]) -> list[int]:
    return [] if len(xs) == 0 else reverse(xs[1:]) + [xs[0]]

def bounded(xs: Annotated[list[int], Refine(lambda v: len(v) <= 2)]) -> Annotated[
    None, Refine(lambda _, xs: reverse(xs) == xs[::-1])
]:
    return None

Select bounded and verify. The source body must pass safety and termination checks before any caller uses its definition. Removing the empty-list guard fails the read obligation; replacing xs[1:] with xs fails descent.

Signatures containing lists unfold three definition layers, with residual calls uninterpreted. Slice expressions grow quickly during substitution; the existing 128 KiB limit still applies. The length bound above leaves enough layers to reach the empty-list base case. Without that bound, this equation is inconclusive: use the explicit inductive lemma below to prove it for arbitrary lengths. Satisfiable residual queries return unknown, including false equations; they do not produce source counterexamples. See Reference.

Prove a list equation

Use ordinary Python list concatenation and slices to define total list helpers:

from __future__ import annotations
import refinepy
from refinepy import Refine
from typing import Annotated

@refinepy.reflect
def append(xs: list[int], ys: list[int]) -> list[int]:
    return xs + ys

@refinepy.reflect
def reverse(xs: list[int]) -> list[int]:
    return xs[::-1]

def reverse_append(xs: list[int], ys: list[int]) -> Annotated[
    None, Refine(lambda _, xs, ys:
        reverse(append(xs, ys)) == append(reverse(ys), reverse(xs)))
]:
    return None

Select reverse_append and verify. The equation covers lists of arbitrary finite length. List equality compares lengths and all valid elements; it ignores internal values outside the list. You can also state append(xs, []) == xs or concatenation associativity. Both operands must have matching recursively comparable element types and element contracts. This example uses nonrecursive definitions and proves the equation for arbitrary finite lists. Recursive list definitions support bounded unfolding as described above; the next example adds an explicit inductive lemma.

Prove a list equation by induction

Use a recursive ordinary lemma with a return proposition and decreases. Each smaller self-call supplies the induction hypothesis. This example proves reverse against a slice for arbitrary finite lengths, then uses that result to prove reverse/append:

from __future__ import annotations
import refinepy
from refinepy import Refine
from typing import Annotated

@refinepy.reflect
@refinepy.decreases(lambda xs: len(xs))
def reverse(xs: list[int]) -> list[int]:
    return [] if not xs else reverse(xs[1:]) + [xs[0]]

@refinepy.decreases(lambda xs: len(xs))
def reverse_spec(xs: list[int]) -> Annotated[
    None, Refine(lambda _, xs: reverse(xs) == xs[::-1])
]:
    if xs:
        reverse_spec(xs[1:])
        return None
    return None

def reverse_append(xs: list[int], ys: list[int]) -> Annotated[
    None, Refine(lambda _, xs, ys: reverse(xs + ys) == reverse(ys) + reverse(xs))
]:
    reverse_spec(xs + ys)
    reverse_spec(xs)
    reverse_spec(ys)
    return None

Select reverse_append and verify. There is no length bound. The driver checks reverse independently, then checks the lemma’s bases, return proposition and strict descent. Removing the self-call leaves the step without its hypothesis; changing it to reverse_spec(xs) fails descent. A wrong base also fails. Successful proofs retain induction:... and termination:... evidence.

This uses one-step ground equations of admitted definitions and the ordinary recursive call contract. Return in each branch to keep the proof local; a merged branch may need qualifier inference and remain inconclusive. This facility requires direct recursion and an integer or lexicographic measure; any loops need their own measures. Mutual induction and automatic proof search are unsupported. Without decreases, a lemma retains partial correctness and carries no induction evidence. See Reference.

Read the results

The results start with counts of Verified, Needs review and Failed selected functions. Needs review groups unproved, unknown and unsupported; Failed groups counterexample and error, whose individual meanings remain visible on each card. An error does not necessarily indicate a source bug. Report-level diagnostics appear separately and prevent an all-verified summary. Each card gives a short conclusion and a separate termination summary. Expand Verification details for solver costs, checked scope, inferred invariants, source dependencies and Proof evidence, including ownership records. Full JSON report retains the complete report.

Each function shows its status, termination summary and diagnostics. A verified result with termination evidence for that exact function shows Termination: verified for this function and its checked calls. Without that evidence, the contract is verified for normal returns and termination is not established. Failed or uncertain results never show a successful termination summary. Python recursion-depth safety and resource availability remain outside the model.

Status Meaning
verified The verifier discharged the required obligations.
counterexample A validated source witness violates the contract.
unproved An obligation remains unproved; this alone does not establish a source bug.
unsupported The source uses a form outside the supported domain.
unknown Limits or solver uncertainty prevented a result.
error Source, contracts, configuration or execution failed; read the diagnostic.

An unknown result can also mean the solver’s complete model could not be reconstructed within the supported representation or resource limits. Reading only a few container elements would not establish a valid model. See the model validation rules. Optional payload facts apply when a value is present. Unused payloads are still checked for a well-formed stored representation. Nested element evidence is checked at every container level, including the string observations made inside its conditions. This internal support does not establish ownership of an extracted nested list.

See Reference for dependent contracts, preconditions, container reads, loop invariants and a summary of supported and unsupported Python forms.

Verify Fibonacci doubling

The example in examples/fibonacci/README.md proves fast doubling against the ordinary Fibonacci recurrence. ensures expresses the return refinements of addition, pair and fast_fib; the None lemma omits a result binder. A recursive addition lemma proves two addition formulas by induction; pair specializes them with addition(k, k) in a static assertion and uses its smaller recursive call’s contract to prove (F(n), F(n + 1)). All four targets verify without an index upper bound. The separate execution checker compares 514 indices with an iterative addition oracle.

The branching recurrence uses a 4 MiB recursive admission preflight; stored one-step definitions, acyclic expansions and query equations retain their smaller bounds. This budget adjustment adds no proof assumptions. See Reference. The example uses a static assertion to avoid executing addition proof calls and evaluates correctness only; it makes no time complexity claim. Python recursion-depth and resource limits remain outside the termination guarantee.
